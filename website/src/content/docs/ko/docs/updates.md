---
title: 업데이트
---

Kitewell은 스스로 최신 상태를 유지합니다. 새 버전을 백그라운드에서 내려받고, Kitewell이 서명한 것인지 확인한 뒤, 사용하지 않는 때에 설치합니다. 실행 중인 워크플로는 다시 시작하는 동안에도 계속 돌아갑니다. 그 아래에서 동작하는 워크플로 엔진 Dagu는 Kitewell 릴리스마다 함께 들어 있으며, Kitewell이 바뀔 때만 바뀝니다.

## 업데이트가 도착하는 방식

**Kitewell 자동 업데이트**는 처음부터 켜져 있으며, **이 기기 → 기기 설정 → 업데이트**에 있습니다. 켜져 있으면 Kitewell은 다음과 같이 합니다.

1. 열린 지 1분 뒤에 새 버전을 찾고, 그 뒤로는 6시간마다 찾습니다.
2. 백그라운드에서 내려받고 서명을 확인합니다. 아무것도 표시하지 않습니다.
3. 다음 안전한 때에 설치합니다. 다음에 Kitewell을 종료하거나, 로그인하거나, 컴퓨터를 다시 시작할 때, 또는 Kitewell 창이 열려 있지 않거나 30분 동안 Kitewell을 쓰지 않은 조용한 때입니다. 메뉴 막대나 트레이의 아이콘이 몇 초 동안 사라졌다가 돌아오고, 열려 있던 창은 같은 페이지로 다시 열립니다.

그다음 **Kitewell이 x.y.z(으)로 업데이트되었습니다**라는 알림이 한 번 표시되며, 클릭하면 kitewell.app의 릴리스 노트가 열립니다.

새 버전은 이틀에 걸쳐 기기에 배포되므로, 모든 컴퓨터가 같은 날 받지는 않습니다. Kitewell 메뉴(Mac에서는 메뉴 막대 메뉴, Windows에서는 트레이 아이콘 메뉴)의 **업데이트 확인…**은 바로 확인하여 릴리스를 즉시 받습니다. 받을 것이 없으면 **Kitewell이 최신 버전입니다**라고 알려 줍니다.

## 업데이트가 기다리는 것

업데이트는 작업을 방해하지 않습니다. 다음 동안에는 기다립니다.

- 어시스턴트가 생각하는 중일 때
- 실행 중인 워크플로에 아직 데스크톱 단계가 남아 있을 때
- MCP 클라이언트가 최근 2분 안에 Kitewell을 사용했을 때
- Kitewell 창에 저장하지 않은 편집이 있을 때

워크플로는 업데이트를 막지 않습니다. 워크플로는 시작할 때의 엔진에서 계속 실행되고, 다시 시작한 Kitewell이 이를 다시 찾습니다.

업데이트가 기다리는 동안 Kitewell 메뉴에는 지금 바로 설치하는 **다시 시작하여 Kitewell x.y.z(으)로 업데이트**가 표시됩니다. 이 항목은 저장하지 않은 편집이 있는지 묻고, 다시 시작하면 중단될 작업을 알려 주며, **지금 다시 시작**과 **유휴 상태일 때**를 제시합니다. 업데이트가 7일 동안 기다렸다면 **업데이트를 완료하려면 Kitewell을 다시 시작하세요**라는 알림이 한 번 표시됩니다. 저장하지 않은 편집 때문에만 하루 동안 기다렸다면, 저장하거나 버리라는 알림이 한 번 표시됩니다. 업데이트 때문에 편집이 버려지는 일은 없습니다.

## 자동 업데이트가 꺼져 있을 때

Kitewell은 여전히 확인합니다. 새 버전이 나오면 알림이 한 번 표시되고, 메뉴에 **Kitewell x.y.z(으)로 업데이트…**가 나타납니다. 이 항목을 선택하면 버전을 내려받으며 진행 상황이 메뉴에 표시됩니다. 그런 다음 Kitewell이 **다시 시작하여 업데이트** 또는 **나중에**를 제시합니다. 선택하기 전에는 아무것도 설치되지 않습니다.

## Dagu Cloud가 더 새로운 Kitewell을 요구할 때

Dagu Cloud는 더 이상 지원하지 않는 버전에 서비스를 멈출 수 있습니다. 워크플로, 일정, 로컬 MCP 서버는 계속 동작하지만, 동기화, 원격 MCP, 웹후크, 실행 상태는 이 컴퓨터가 업데이트될 때까지 멈춥니다. 창의 배너가 이를 알리고 **지금 업데이트**를 제시합니다. 이 버튼은 설정과 상관없이 릴리스를 바로 가져와 다음 안전한 때에 설치하거나, 1시간 뒤에 다시 시작하도록 요청합니다.

## 비밀번호가 필요한 Mac에서

Kitewell은 macOS 사용자가 앱을 소유하고 응용 프로그램 폴더에 쓸 수 있을 때만 비밀번호 없이 스스로를 교체합니다. 일반(관리자가 아닌) 계정이거나, 다른 사용자나 기기 관리로 Kitewell이 설치된 경우에는 백그라운드에서 아무것도 내려받지 않습니다. 메뉴에 **Kitewell x.y.z(으)로 업데이트…**가 표시되고 알림이 한 번 나옵니다. 이 항목을 선택하면 업데이트를 내려받고 macOS의 관리자 확인이 표시됩니다. Kitewell은 요청하지 않은 관리자 확인을 표시하지 않습니다.

## 문제가 생겼을 때

- 다운로드나 그 확인이 실패합니다. Kitewell은 다음 확인 때 조용히 다시 시도합니다. 메뉴를 열면 이유가 표시됩니다.
- 설치가 실패합니다. 설치된 버전이 그대로 남고 Kitewell이 다시 시작합니다. 다음 안전한 때에 다시 시도합니다. 한 버전의 설치가 세 번 실패하면 Kitewell은 그 버전을 더 이상 시도하지 않고, [다운로드 페이지](/ko/download/) 링크와 함께 **Kitewell을 업데이트할 수 없습니다**를 표시합니다.
- 확인 자체가 실패합니다. 네트워크와 [릴리스 상태](/ko/releases/)를 확인하세요. 사용 중인 시스템의 첫 공개 릴리스가 나오기 전에는 읽을 업데이트 피드가 없으며, 피드에 닿지 못한 확인은 최신 버전이라고 주장하지 않고 그렇다고 알려 줍니다.
- 이전 버전으로 돌아가야 합니다. 이전 설치 프로그램은 [GitHub 릴리스 페이지](https://github.com/dagucloud/kitewell/releases)에 남아 있습니다. 이전 앱을 설치해도 이전 데이터는 돌아오지 않습니다. 그때는 [백업](/ko/docs/backups/)을 복원하세요.

문제를 알려 주실 때는 Kitewell 버전, 엔진 버전, 운영 체제 버전을 함께 적어 주세요. 사이드바 왼쪽 아래에 Kitewell 버전이 표시됩니다. 상단 막대의 배지에는 Kitewell 버전과 엔진 버전이 함께 표시됩니다. Mac에서는 애플리케이션 메뉴의 **Kitewell에 관하여**가 Kitewell 버전을 보여 주고, Windows에서는 트레이 메뉴 맨 위에 앱과 서비스 버전이 표시됩니다.

## 세부 정보

- 공개 빌드는 업데이트 피드를 Mac에서는 `https://kitewell.app/updates/macos/latest.json`, Windows에서는 `https://kitewell.app/updates/windows/latest.json`에서 읽습니다.
- 확인하고 내려받는 동안 워크플로는 계속 실행됩니다. 무언가를 다시 시작하는 것은 설치뿐입니다.
- 다운로드는 디스크 여유 공간이 2GB 있고 데이터 통신량 제한이 없는 연결일 때까지 기다립니다. 내려받았지만 아직 설치하지 않은 업데이트는 그 릴리스가 일시 중지되거나 교체되면 버려집니다.
- 업데이트 후 알림은 버전마다 한 번만, Kitewell의 알림이 허용된 곳에서만 표시됩니다.
- Windows에서 업데이트는 교체하는 몇 초 동안 백그라운드 서비스를 멈추지만, 그 아래의 실행은 멈추지 않습니다. 실행마다 자기 프로세스 그룹이 있기 때문입니다. 실행을 취소하는 것은 **Kitewell 종료**뿐입니다.
- Kitewell이 실행하는 엔진은 해당 버전의 Kitewell에 들어 있는 Dagu 릴리스이며, 릴리스 노트와 [서드파티 라이선스 페이지](/third-party/)에 그 이름이 나와 있습니다.
