[Excel 자동화](/ko/docs/spreadsheets/)에서 다루지 않은 워크북에 관한 모든 것입니다. 스프레드시트 단계는 모든 요금제에 있습니다.

## 워크북을 쓰는 두 가지 방법

시트의 행으로 쓰기: 워크북을 시트에 연결하면 각 행이 하나의 실행이 되고, 그 결과가 같은 행으로 돌아갑니다. 워크북 자체가 *곧* 할 일, 즉 처리해야 할 일의 목록일 때 쓰세요.

워크플로 안의 단계로 쓰기: 작업 선택기의 **스프레드시트** 그룹에서 작업을 추가하고 파일 경로를 지정하면, 실행의 그 지점에서 읽거나 씁니다.

워크북이 더 큰 일의 일부일 때 쓰세요. 이메일로 도착하는 파일이나, 템플릿으로 채우는 월별 청구서 같은 경우입니다.

## Kitewell이 읽는 것

사무실에 이미 있는 워크북을 그대로 읽습니다. 표 위의 제목 행, 두 행에 걸쳐 병합된 머리글, 중간의 소계, 아래의 메모, 전각 숫자, 일본 연호 날짜, 앞자리 0이 있는 우편번호가 있어도, Kitewell이 표가 어디 있는지와 각 열에 무엇이 들어 있는지 알아냅니다.

이번 릴리스에서는 연결된 시트가 전각 숫자와 텍스트로 적힌 연호 날짜를 텍스트 그대로 워크플로에 넘깁니다. 스프레드시트 단계는 이것들을 숫자와 날짜로 읽습니다.

워크북을 연결하면 미리 보기의 각 행이 **3행을 열 이름으로 사용**을 제시하고, 단순한 목록이라면 **열 이름 없음**도 고를 수 있습니다. 열 이름 위의 행, 빈 행, 합계 행은 각각 개수를 센 뒤 제외됩니다.

체크박스 하나로 합계 행을 포함할 수 있고, 다른 하나로 Excel에서 숨긴 행을 뺄 수 있습니다.

**행을 다시 찾는 기준**에는 값이 겹치지도 비어 있지도 않은 열만 고를 수 있습니다. 나머지 열은 "값이 중복되거나 비어 있음"으로 흐리게 표시됩니다. **행 위치**는 대체 수단이며, 이때는 결과가 남아 있는 동안 행을 정렬하거나 삽입하면 안 됩니다.

## 파일로 돌아가는 것

시트에 되돌려 쓸 이름의 열이 있으면 그 열을 쓰고, 새 이름이면 오른쪽에 열을 추가합니다. 실행 ID, 내부 키 열, 셀 메모는 추가하지 않습니다. 영어 머리글의 워크북에서는 "Run at" 열이 `2026-10-01 09:30` 형식으로 쓰입니다.

단어는 워크북 자체 머리글의 언어를 따릅니다. 머리글이 일본어인 시트에는 状態, エラー, 実行日時와 済 / 一部失敗 / 失敗 / 中止 / 却下가 쓰이고, 머리글이 중국어나 한국어면 같은 단어가 중국어나 한국어로 쓰입니다. 한국어 머리글이라면 상태, 오류, 실행 시각과 완료 / 일부 실패 / 실패 / 중지됨 / 거부됨입니다. 한자로만 된 머리글은 Kitewell을 중국어로 읽을 때만 중국어로 봅니다. 그 밖의 머리글에는 영어 단어가 쓰입니다.

Excel이 저장하지 않고 닫히면서 잠금 파일을 남겼다면 **열려 있지 않습니다**가 그것을 지웁니다. 사본도 같은 방식으로 파일 이름의 언어에 따라 `(results)` 대신 `(結果)`, `(结果)`, `(결과)`로 이름이 붙습니다.

**되돌리기**는 쓴 뒤에 워크북을 편집했다면 그 편집을 버리지 않고 거부하며, 현재 파일을 `supplier-invoices (before undo).xlsx`로 옆에 남깁니다. 이번 릴리스에서는 다음에 쓸 때 되돌린 결과가 다시 들어갑니다.

**워크북 다시 읽기**는 찾은 내용을 "1 new · 1 updated · 1 no longer in the sheet"처럼 알려 줍니다. 머리글 행에서 키 열이나 입력이 쓰는 열이 사라졌다면 읽기를 멈추고 무엇이 없어졌는지 알려 줍니다. 워크북을 다시 연결해 열을 다시 고르세요.

**연결 해제**는 연결을 끝냅니다. 행은 시트에 남고, 결과는 더 이상 돌아가지 않습니다.

## 스프레드시트 단계

워크플로 안에서는 작업 선택기의 **스프레드시트** 그룹이 열 가지 작업을 제공합니다.

| 작업 | 하는 일 |
| --- | --- |
| 스프레드시트 읽기 | 시트에서 원하는 행만, 각 열을 텍스트, 숫자, 날짜로 읽기 |
| 스프레드시트 검사 | 셀이 잘못되었을 때 다른 일이 일어나기 전에 멈추기 |
| 결과 되돌려 쓰기 | 상태와 값을 원래 행에 쓰기 |
| 스프레드시트 쓰기 | 새 워크북이나 시트를 교체하거나 덧붙이기 |
| 스프레드시트에 행 추가 | 머리글에 맞춰 마지막 행 아래에 행 추가 |
| 템플릿 채우기 | 템플릿의 셀이나 이름 있는 셀을 채워 사본으로 저장 |
| 스프레드시트 변환 | 시트를 CSV(UTF-8 또는 Shift_JIS), JSON, JSON Lines로 |
| 시트 추가·복사·이름 바꾸기·삭제 | 템플릿 시트로 한 달을 시작하고, 안전하게 다시 실행 |
| 워크북 살펴보기 | 이후 단계를 위한 시트, 머리글, 형식 |
| 양식 읽기 | 양식으로 꾸민 견적서나 주문서의 항목을, 배치와 관계없이 |

단계에서 **워크북**을 고르면 시트가 탭으로 표시되고, 처음 20개 행이 단계가 읽을 형태로 변환되어 나오며, 찾아낸 표와 머리글 행이 표시됩니다.

**확인**은 무엇이든 실행하기 전에, 이 컴퓨터에서 단계가 실패할지(워크북, 시트, 열이 없는지) 엔진에 물어봅니다. 답에 나오는 셀 주소는 모두 그 셀을 보여 주는 버튼입니다.

**테스트**는 행을 표로 보여 줍니다. 쓰는 단계는 **테스트 중에도 파일 저장**에 체크하지 않으면, 테스트 중에는 무엇이 바뀔지만 알려 줍니다. 스프레드시트 변환은 예외로, 테스트하면 실제로 출력 파일을 씁니다.

이후 단계가 참조하는 열에는 "Invoice No"에 대한 `invoice`처럼 영문자로 된 짧은 이름이 필요합니다. **스프레드시트 읽기**에서 각 열 옆의 **이후 단계용 이름**에 입력하며, 편집기가 이름을 제안합니다.

쓰는 단계에는 세 가지 설정이 있습니다. 저장하지 않고 변경 내용만 알려 주는 **모의 실행**, Excel에서 열려 있는 워크북을 단계가 실패하기 전에 다시 시도하는 몇 분까지의 대기, 그리고 기본으로 켜져 있어 반쯤 쓰다 만 워크북이 남지 않게 임시 파일을 거쳐 저장하는 설정입니다.

## 같은 일을 단계로

워크북이 더 큰 워크플로의 일부라면, 청구서 작업을 연결된 시트 대신 단계로 만드세요.

1. **스프레드시트 읽기**가 Invoices 시트를 읽습니다. **다음 조건의 행만…**에서 Status 열을 고르고 값을 비워 두면, 아직 처리하지 않은 청구서만 읽습니다.
2. **각 항목 처리**가 그 행들을 하나씩 처리합니다.
3. 반복 안에서 포털에 청구서를 등록하는 단계를 둡니다. [웹사이트 단계](/ko/docs/browser/), [데스크톱 단계](/ko/docs/desktop/), 또는 명령입니다. 이 단계가 접수 번호를 만듭니다.
4. 여전히 반복 안에 있는 **결과 되돌려 쓰기**가 청구서가 온 행의 Status에 `Done`을, Receipt No에 접수 번호를 씁니다.

되돌려 쓰기가 반복 안에 있으므로, 실패한 행은 Status가 빈 채로 남고 다음 실행이 다시 처리합니다. 그 사이에 무엇이 있든 스프레드시트 단계는 화면을 쓰지 않습니다.

## 표가 아닌 양식

양식으로 꾸민 견적서나 주문서, 즉 머리글 아래 행이 아니라 라벨과 값이 시트 곳곳에 흩어진 것은 **양식 읽기**가 읽습니다.

**이 양식이 무엇이고 무엇을 찾을지**에는 양식이 무엇인지 적습니다. **찾을 항목**에는 각 항목의 이름, 형식, 그리고 시트에서 그 라벨이 어떻게 보이는지를 시트의 언어로 적습니다.

모델은 각 항목이 있는 셀을 답하고, 엔진이 그 셀에서 값을 직접 읽으므로 값을 지어내지 않습니다.

**셀의 값을 모델에 보내기**를 끄면 모델은 각 셀에 어떤 종류의 내용이 있는지만 보게 되므로, 금액과 날짜가 이 컴퓨터에 남습니다.

**이 레이아웃을 기억해 같은 양식은 모델 없이 읽기**는 기본으로 켜져 있으므로, 같은 템플릿에는 모델 호출이 더 들지 않습니다. **기억한 셀 잊기**를 쓰면 다음 실행이 다시 물어봅니다. 양식의 배치가 바뀌었거나, 항목을 엉뚱한 셀에서 읽었을 때 쓰세요.

## 개인 정보

- 워크북은 이 컴퓨터에서 Kitewell이 읽습니다. 파일은 절대 업로드되지 않으며, 경로도 기기 밖으로 나가지 않습니다.
- **이 파일에서 설정**은 열려 있는 워크북으로 워크플로를 만들어 달라고 어시스턴트에게 요청합니다. 열 이름, 각 열에서 본 형식, 그리고 각 셀을 한 줄로 자른 처음 10개 행을 보냅니다. **열 이름만 보내기**는 이름만 보냅니다.
- 비밀번호가 있는 워크북은 이 컴퓨터에서만 엽니다. 비밀번호는 **암호(시크릿 참조)**에 [시크릿](/ko/docs/secrets/) 참조로 보관되며, 워크플로에 적히지도 로그에 남지도 않습니다. 보호된 워크북은 미리 볼 수 없고, Excel에서 비밀번호를 없애기 전에는 가져올 수도 없습니다.
- [Dagu Cloud와 동기화](/ko/docs/cloud-sync/)되는 연결에는 파일 이름, 시트, 파일이 있는 기기, 열 매핑이 담기며, 경로는 담기지 않습니다. 시트의 행도 함께 가며, 그 행에는 워크북에서 읽은 셀 값이 들어 있습니다.
- 파일 경로, 시트의 각 행이 어느 Excel 행에서 왔는지, 실행에서 읽은 결과, 되돌리기용으로 보관한 사본은 시트를 실행한 기기에 남습니다. 다만 [워크스페이스 백업](/ko/docs/backups/)에는 그 사본이 들어갑니다.

전체 그림은 [컴퓨터 밖으로 나가는 것](/ko/docs/data-flow/)을 참고하세요.

## 제한

- `.xlsx`와 `.xlsm`. `.xls`나 `.ods` 파일은 먼저 Excel에서 `.xlsx`로 저장해야 합니다.
- 한 번에 5,000행, 약 900KB까지 읽습니다. 어느 쪽이든 넘으면 단계가 무엇을 남겼는지 알려 주고, 더 좁은 범위, 더 적은 열, 또는 행 필터를 요청합니다.
- 시트에는 5,000행과 결과 열 30개, 반복에는 1,000개 항목까지 들어갑니다. 가져오는 파일은 최대 16MiB입니다.
- 연결된 워크북의 숨긴 행은 나머지와 함께 읽힙니다. 숨긴 행을 빼는 선택지는 가져온 파일에만 있습니다.
- 파일에 이미 있는 차트, 피벗 테이블, 조건부 서식, 유효성 검사 규칙은 유지되지만 새로 만들지는 않으며, 피벗 테이블은 새로 고치지 않습니다. Windows에서는 매크로 단계로 새로 고칠 수 있습니다.
- Google 스프레드시트는 아직 지원하지 않습니다.

웹사이트나 데스크톱 앱을 조작하는 단계는 여전히 그 애플리케이션이 필요하므로, 화면을 쓰지 않는 것은 스프레드시트 단계뿐입니다.
