[일정과 백그라운드 동작](/ko/docs/scheduling/)에서 다루지 않은 일정에 관한 모든 것입니다.

## 판정의 의미

예약된 워크플로에는 다섯 가지 판정 중 하나가 붙습니다. **워크플로** 목록에서는 다음 시작 아래에, 일정 편집기에서는 예측 아래에 표시됩니다.

- **실행됩니다**, 또는 Windows 서비스를 켠 뒤에는 **로그인 여부와 관계없이 실행됩니다**: 방해하는 것이 없습니다. 기기가 배터리로 동작 중이라는 것처럼, 뒤에 붙는 메모가 알아 둘 점을 알려 줍니다.
- **로그인한 동안에만 실행됩니다**: 실행은 되지만, 누군가 로그인해 Kitewell을 열어 두었을 때만입니다. Windows에서는 서비스가 꺼져 있을 때, 그리고 데스크톱 단계나 보이는 브라우저 창이 있는 워크플로라면 서비스가 켜져 있을 때도 그렇습니다.
- **실행되지 않습니다**: 무언가가 막고 있습니다. 이유와 해결 방법이 뒤따릅니다.
- **일시 중지됨**: 워크플로의 일정이 일시 중지되어 있습니다.
- **수동 실행만**: 워크플로에 일정이 없습니다.

판정이 알려 줄 수 있는 이유는 다음과 같으며, 심각한 것부터 나열했습니다.

- 로그인 서비스가 엔진을 시작할 수 없습니다. 비밀번호가 거부되었거나 없거나, 계정이 잠겼거나 비활성화되었거나 만료되었거나, 일괄 작업으로 로그온할 권한이 거부되었습니다.
- 프로젝트가 일시 중지되었거나, 엔진이나 스케줄러가 실행 중이 아닙니다.
- 워크플로가 보류되었거나, 일정을 읽을 수 없습니다.
- 비밀번호가 곧 만료됩니다.
- 전원 관리 옵션이 절전 해제 타이머를 허용하지 않습니다.
- 기기가 배터리로 동작 중입니다.
- 브라우저 로그인에 비밀번호가 필요합니다.
- 일정의 시간대가 기기의 시간대와 다릅니다.

이유마다 해결 방법이 하나 있으며, 이유가 표시되는 곳에 버튼으로 제공됩니다. 서비스 켜기, 비밀번호 업데이트 또는 추가, IT 담당자용 텍스트 복사, 프로젝트 재개, 엔진 시작 또는 다시 시작, 워크플로나 일정 편집, 기기 설정 열기입니다.

판정은 무언가 바뀌면 1분 안에, 워크플로를 저장하거나 엔진이 시작하거나 멈추면 바로 다시 계산됩니다.

## 첫 일정

기기에서 워크플로에 처음으로 활성 일정이 생기면, **워크플로** 목록 위의 카드가 판정과 **지금 예약 테스트**와 함께 한 번 알려 줍니다. **확인**을 누르면 사라집니다.

## 지금 예약 테스트

예약 실행이 쓰는 것과 같은 대기열과 같은 규칙으로 워크플로를 한 번 실행하고 그 실행을 엽니다. 이 실행은 **예약 테스트**로 표시됩니다. 놓친 예약 시각을 대신하지는 않습니다.

## Windows 로그인 서비스

**로그인하지 않아도 실행**을 켜면 Kitewell sign-in이라는 Windows 서비스가 PC가 시작될 때 실행 계정으로 엔진을 시작하고 계속 실행합니다.

실행 계정은, 비밀번호를 저장하지 않은 작업을 Windows 작업 스케줄러가 실행하는 방식대로 비밀번호 없이 로그인한 본인입니다. Windows Server에서는 Kitewell이 만드는 로컬 계정 `Kitewell Runner`이고, 비밀번호와 함께 지정한 다른 계정일 수도 있습니다.

이렇게 하면 다음과 같은 이점이 있습니다.

- 다시 시작한 뒤 누군가 로그인하기 전에도 일정이 실행됩니다.
- 예약 실행 5분 전부터 2분 뒤까지 PC를 깨어 있게 하고, 전원 관리 옵션이 절전 해제 타이머를 허용하면 다음 실행 1분 전에 타이머를 맞춥니다.
- 로그인하면 엔진이 내 세션으로 옮겨 와 데스크톱 단계가 내 화면에 닿고, 로그아웃하면 다시 돌아갑니다.

다음은 하지 않습니다.

- 아무도 로그인하지 않은 동안 데스크톱 단계나 보이는 브라우저 창에 화면을 주는 것. 그런 워크플로는 **로그인한 동안에만 실행됩니다**로 표시됩니다.
- **내 비밀번호 사용…**으로 비밀번호를 추가하기 전에, 네트워크 공유나 Windows가 비밀번호로 보호하는 로그인에 닿는 것. 판정이 비밀번호가 필요한 워크플로를 알려 줍니다.
- 파일이 저장되는 곳을 바꾸는 것. 실행은 여전히 내 폴더와 설정을 가진 나로서 이루어집니다.

Setup.exe는 관리자 확인 없이 내 계정에 Kitewell을 설치하므로 서비스를 설정하지 않습니다. 앱이 열리면 **기기 설정 → 로그인하지 않아도 실행**에서 켜세요. 관리자 확인을 거절했거나 설정이 중간에 멈추면 기록되며, 기기 카드가 그렇게 알리고 기능을 다시 제안합니다.

업데이트 후에는 서명된 Kitewell이 서비스가 쓰는 프로그램 사본을 확인 없이 스스로 새 버전으로 맞춥니다.

서비스의 프로그램은 `C:\Program Files\Kitewell`에, 데이터는 내 데이터 폴더에서 한 번 옮겨진 `C:\ProgramData\Kitewell`에 있습니다. 기능을 끄면 서비스는 제거되고 데이터는 그 자리에 남습니다.

시작, 중지, 거부된 로그인, 설정은 모두 이벤트 뷰어의 **Kitewell sign-in** 원본 아래에 기록됩니다. 추가한 비밀번호는 Windows가 서비스 비밀번호를 보관하는 것과 같은 보호된 저장소에 보관하며, Kitewell의 파일에는 절대 저장하지 않습니다.

## 놓친 실행

실행 없이 지나간 예약 시각은 네 가지 이유 중 하나와 함께 기록됩니다.

| 표시되는 이유 | 일어난 일 |
| --- | --- |
| 기기가 절전 모드였습니다 | 컴퓨터가 그 시각에 잠자기 상태였습니다 |
| Kitewell이 실행되고 있지 않았습니다 | Kitewell, 또는 Windows에서는 서비스가 실행되고 있지 않았습니다 |
| 프로젝트 엔진이 실행되고 있지 않았습니다 | 프로젝트가 일시 중지되었거나 엔진이 멈춰 있었습니다 |
| 실행이 시작되지 않았습니다 | 모두 동작 중이었는데 엔진이 시작하지 않았습니다 |

앞의 셋은 기기 쪽 원인이고, 마지막은 워크플로 쪽 원인입니다. **실행 및 로그**에서는 **놓침** 행이 예약 시각에 실행들 사이에 이유와 함께 놓이고, **놓침** 탭은 그것만 나열합니다.

행에는 **따라잡기가 켜져 있어 엔진이 가능할 때 실행합니다.**, **따라잡기가 꺼져 있어 나중에 실행되지 않습니다.**, 또는 그 실행을 여는 **09:00의 실행으로 따라잡았습니다.** 같은 문구가 표시됩니다. 놓침 행은 다시 시도하거나 삭제할 수 없으며, 실행 기록과 함께 오래되면 사라집니다.

Windows에서는 밤사이 자리를 비운 뒤 로그인하면 표시되는 줄이 이를 셉니다. "실행 12회, 1회 실패, 예약 실행 2회가 시작되지 않음"과 같은 식입니다.

## 따라잡기

따라잡기는 컴퓨터가 돌아온 뒤 놓친 시작을 실행합니다. 워크플로 하나에 대해서는 **일정 → 놓친 일정**에서 바꿉니다.

- **놓친 일정 따라잡기**: **프로젝트 기본값에 따름**, **끄기**, 또는 **되돌아볼 기간 지정**.
- **되돌아볼 기간**: 얼마나 거슬러 볼지, 최대 30일. 기본값은 24시간입니다.
- **놓친 일정 처리 방식**: **놓친 회차를 모두 실행**, **놓친 회차 중 최신 항목만 실행**, 또는 **실행 중일 때는 건너뛰기**.

**프로젝트 설정 → 워크플로 기본값**은 프로젝트에 대해 같은 것을 정하고, **기기 설정 → 워크플로 기본값**은 새 프로젝트의 초깃값만 정합니다. 워크플로마다 놓친 시작은 최대 1,000개까지 보관됩니다.

Kitewell Personal이나 Team에서는 [놓친 일정 알림](/ko/docs/alerts/)이 시작되지 않은 예약 실행의 수와 이유를 알려 줍니다.

## 더 많은 일정, 일시 중지, 웹후크

워크플로에는 일정을 여러 개 둘 수 있고, 정한 시각에 멈추거나 다시 시작하게 할 수도 있습니다. 이것들은 **추가 일정**에 있습니다. **워크플로** 목록의 **일정 일시 중지**는 워크플로 하나를 순번에서 뺍니다. 워크스페이스에서 내려받은 프로젝트는 워크플로가 일시 중지된 상태로 도착합니다.

워크플로는 다른 서비스가 요청을 보낼 때 시작할 수도 있습니다. **일정** 보기에서 **웹후크**를 켜세요. 요청에 무엇이 담기는지는 [웹후크로 워크플로 시작하기](/ko/docs/webhooks/)에 있습니다.

웹후크 주소는 `https://hooks.kitewell.app/…` 형태이며, 요청은 POST여야 하고 응답은 `202`입니다. 단계는 본문을 `$WEBHOOK_PAYLOAD`에서, 헤더를 `$WEBHOOK_HEADERS`에서 읽습니다.

웹후크는 분당 약 60개 요청, 최대 512KiB의 본문, 최대 16KiB의 헤더를 받으며, 최근 요청 20개를 **최근 요청**에 보관합니다. Windows에서는 명령줄 길이 제한 때문에 약 32,000자를 넘는 본문으로는 실행이 시작되지 않을 수 있습니다.

## 대기열

대기열은 모든 것이 한꺼번에 시작되지 않게 합니다. 모든 프로젝트에는 한 번에 5개를 실행하는 **default** 대기열이 있습니다. **더 보기 → 대기열**에서 **동시 실행 수**로 바꾸거나 직접 추가하세요. 워크플로는 **설정**에서 대기열을 고릅니다.

대기열은 수동 시작, 따라잡기 실행, 재시도, 웹후크 실행, 예약 테스트, [일괄 처리](/ko/docs/batches/) 행의 속도를 조절합니다. 일정에 따라 제시간에 시작하는 실행은 붙잡지 않습니다. 프로젝트가 정의하지 않은 대기열은 한 번에 하나씩 실행합니다.

## 혼자 돌아가게 두기 전에

- 명령은 실행 계정의 권한으로 실행됩니다.
- Docker 단계에는 실행 중인 Docker가 필요합니다.
- AI 단계에는 이 기기에 설정된 모델이나 에이전트가 필요합니다.
- 다른 컴퓨터에서 실행하는 단계에는 그 컴퓨터에 연결할 수 있고 호스트 키가 승인되어 있어야 합니다.
- [웹사이트 단계](/ko/docs/browser/)에는 Chrome과 성공한 **브라우저 확인**이 필요합니다.
- 이 기기에 값이 없는 시크릿이 필요한 실행은 시작할 때 실패합니다.

## 메뉴 항목

메뉴 막대와 알림 영역의 항목은 Kitewell을 읽는 언어로 표시됩니다. **Kitewell 열기**, **Kitewell 종료**, **워크플로 실행 중 깨어 있게 유지**, 그리고 Mac에서는 **로그인 시 열기**, Windows에서는 **로그인 시 시작**입니다. Mac에는 **메뉴 막대에서 계속 실행**도 있고, 서비스를 켠 Windows에는 **백그라운드 서비스 업데이트…**가 더해집니다.

두 메뉴 모두 프로젝트를 나열하므로 프로젝트마다 따로 시작하고 멈출 수 있습니다. Mac에서 **Kitewell 종료**는 모든 것을 멈추며, 진행 중인 실행이 있으면 먼저 경고합니다. 서비스를 켠 Windows에서는 창을 닫고 엔진과 그 실행은 서비스에 맡깁니다.

## 세부 정보

- 실행 기록은 처음에 30일 동안 보관되며 **기기 설정 → 실행 기록 보관**에서 바꿉니다. [실행 및 로그](/ko/docs/runs/)를 참고하세요.
- Mac의 잠자기 방지(**기기 설정 → 잠자기 방지**)는 작업이 실행되는 동안 컴퓨터를 깨어 있게 합니다. 처음에는 꺼져 있으며, 아직 시작되지 않은 일정을 위해 컴퓨터를 깨우지는 않습니다.
- Windows 서비스는 `KitewellSignin`으로 등록된 `kitewell-signin.exe`이며, `sc query KitewellSignin`으로 상태를 볼 수 있습니다. 설정 로그는 `%LOCALAPPDATA%\Kitewell\logs\signin-setup.log`입니다.
