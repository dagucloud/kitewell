---
title: 计划与后台运行
---

Kitewell 可以替你启动工作流：每个工作日 9:00、每小时一次，或者在其他服务向它发送请求时。工作在这台电脑上进行。在 Windows 上，无论你是否登录都会进行；在 Mac 上，只在你登录期间进行。

## 设置计划

1. 打开工作流，选择 **计划**。
2. 确认已勾选 **启用已保存的计划**。
3. 在 **运行** 下选择频率：**每天**、**工作日**、**每周**、**每小时** 或 **自定义计划**。
4. 设置时间。自定义计划使用由五个字段组成的 cron 表达式。
5. 如果时间对应的是某个特定地点，请打开 **时区**。不设置时，计划按这台电脑的时钟运行，夏令时也会自动计入。
6. 选择 **保存**。

![工作流的“计划”标签页，显示已保存计划的开关、工作日计划及其时间](../../../../assets/docs/zh/scheduling-schedule-tab.png)

表单下方的 **接下来的 5 个计划事件** 显示工作流实际会在什么时候运行。再往下有一行字，说明这个计划在这台电脑上的结果：**无论是否登录都会运行**、**仅在您登录时运行** 或 **不会运行**，并附上原因和解决问题的按钮。

**立即测试计划** 会完全按照计划的方式运行一次工作流，并打开这次运行。在把夜间的运行交给计划之前，先用它试一下。

## 确认今晚的运行会进行

**工作流** 列表中，每个工作流的下次启动时间下方也会显示同样的判断结果；页面顶部的横幅会用一行字说明有什么会妨碍今晚的运行，并在旁边给出解决办法。没有任何妨碍时，不会显示横幅。

判断时会检查：这台电脑届时是否处于登录状态、项目及其引擎、已暂停或被搁置的工作流、需要使用屏幕的步骤、需要你密码的浏览器登录，以及按其他时区编写的计划。

<a id="run-with-nobody-signed-in-windows"></a>

## 无人登录时也运行（Windows）

开启 **设备设置 → 无人登录时也运行**。只需确认一次管理员提示，无需输入密码，就会设置一个名为 Kitewell sign-in 的小型 Windows 服务。它会在电脑启动时启动引擎，并以你的身份运行计划，无论你是否登录。

那里的卡片会显示运行账户、登录状态、引擎、下一次计划运行和睡眠情况，也可以在那里重新关闭该服务。

有两类步骤仍然需要你在电脑前：桌面步骤，以及会显示浏览器窗口的网站步骤。包含这类步骤的工作流会显示 **仅在您登录时运行**。其他步骤无论是否登录都会运行。

卡片上的 **使用我的密码…** 是可选的。当工作流需要访问网络共享，或需要 Windows 用你的密码保护的网站登录信息时，请添加密码。**忘记密码** 会将其移除。Microsoft 账户或工作账户可能在登录本身就需要密码；这时卡片会加以说明并请你输入。

## 让 Kitewell 保持运行

关闭窗口不会停止任何东西：在 Mac 上，Kitewell 会留在菜单栏中；在 Windows 上，会留在通知区域中。Mac 上的 **登录时打开** 和 Windows 上的 **登录时启动** 会在你登录时打开它。在 Mac 上，**退出 Kitewell** 会停止引擎；在 Windows 上，如果服务已开启，即使没有窗口，引擎也会继续运行。

<a id="sleep-and-the-runs-that-were-missed"></a>

## 睡眠与错过的运行

在 Windows 上，服务开启时，电脑会在计划运行前后保持唤醒；如果电源计划允许唤醒定时器，还会从睡眠中唤醒以进行下一次运行。在 Mac 上，处于睡眠状态的电脑不会运行任何东西；**设备设置 → 睡眠防护** 会在工作进行期间让电脑保持唤醒。

计划时间过去却没有运行时，**运行与日志** 中会出现一行 **未运行**，并说明原因：设备处于睡眠状态、Kitewell 未运行、项目引擎未运行，或没有启动运行。该行会说明补跑是否会补上这次运行，并链接到补上的那次运行。

电脑恢复后，补跑会运行错过的启动，默认回溯 24 小时。可以在 **计划 → 漏掉的计划** 中更改。

## 遇到问题时

- **时间到了，却什么都没有运行。** 打开 **运行与日志**，找一行 **未运行**：其中写明了原因。然后查看工作流下次启动时间下方的判断结果。
- **在错误的时间运行了。** 检查计划的 **时区**，以及 **接下来的 5 个计划事件** 中的时间。
- **电脑唤醒后同时启动了好几个运行。** 这是补跑。将 **漏跑处理策略** 设为 **仅运行最新漏掉的一次**，或将补跑设为 **关闭**。
- **判断结果显示“不会运行”。** 按下旁边的按钮。它会根据原因开启服务、请求密码、启动引擎或打开编辑器。

更多内容请参阅[故障排除](/zh/docs/troubleshooting/)。
