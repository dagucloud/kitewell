这里汇总了[自动处理 Excel](/zh/docs/spreadsheets/)中没有介绍的、关于工作簿的全部内容。所有套餐都提供电子表格步骤。

## 使用工作簿的两种方式

作为表格的行：把工作簿链接到一个表格，每一行就成为一次运行，其结果会写回该行。如果工作簿本身*就是*要完成的工作，也就是一份待处理的清单，请使用这种方式。

作为工作流中的步骤：从任务选择器的 **电子表格** 组中添加任务，并指定文件路径，它就会在运行的那个环节读取或写入。

如果工作簿只是一项更大工作的一部分，例如通过邮件收到的文件、根据模板填写的月度发票，请使用这种方式。

## Kitewell 能读取什么

它能读取你办公室现有的工作簿。表格上方的标题行、跨两行合并的表头、中间的小计、下方的备注、全角数字、日本年号日期、以零开头的邮政编码：Kitewell 会判断表格在哪里，以及每一列包含什么。

在当前版本中，已链接的表格会把以文本形式写的全角数字和年号日期，作为文本传给工作流。电子表格步骤则会把它们读取为数字和日期。

链接工作簿时，预览的每一行都提供 **将第 3 行用作列名**，对于没有表头的清单，还有 **没有列名** 可选。列名上方的行、空行和合计行会被排除，并分别显示数量。

有一个复选框可以选择仍然包含合计行，另一个可以排除在 Excel 中隐藏的行。

只有值从不重复且从不为空的列，才能在 **重新找到行的依据** 下选择；其余的列会以灰色显示，并标注“值重复或缺失”。**行位置** 是备用选项，选择它之后，在结果尚未写回期间，你不能对行排序或插入行。

## 哪些内容会写回你的文件

如果表格中已有与写回列同名的列，就使用该列；如果是新名称，则在最右侧添加一列。不会添加运行 ID、内部键列或单元格批注。**Run at** 的写入格式为 `2026-10-01 09:30`。

写入的文字跟随工作簿自身表头的语言：表头为日文的工作表，会写入 状態、エラー、実行日時 以及 済 / 一部失敗 / 失敗 / 中止 / 却下；表头为中文或韩文时，会以中文或韩文写入同样的文字，中文为 状态、错误、运行时间 以及 完成 / 部分失败 / 失败 / 已停止 / 已拒绝。只有当你以中文使用 Kitewell 时，仅由汉字组成的表头才会被视为中文。其他表头会写入英文。

如果 Excel 未保存就关闭并留下了锁定文件，**它未被打开** 可以将其清除。副本的名称同样跟随文件名的语言，加上 `(結果)`、`(结果)` 或 `(결과)`，而不是 `(results)`。

如果写入之后你编辑过工作簿，**撤销** 会拒绝执行，以免丢弃你的编辑，并把当前文件另存在旁边，名为 `supplier-invoices (before undo).xlsx`。在当前版本中，下一次写入会再次写入被撤销的结果。

**重新读取工作簿** 会报告它发现的变化，例如“新增 1 行 · 更新 1 行 · 1 项已不在工作表中”。如果表头行中缺少了键列或某个输入所用的列，读取会停止，并写明缺少的内容；请重新链接工作簿以重新选择列。

**取消链接** 会结束这种关联：各行保留在表格中，结果不再写回。

## 电子表格步骤

在工作流中，任务选择器的 **电子表格** 组提供十个任务：

| 任务 | 作用 |
| --- | --- |
| 读取电子表格 | 读取工作表中的行，只取你需要的行，每列按文本、数字或日期读取 |
| 检查电子表格 | 单元格有误时，在其他任何操作发生之前停止 |
| 回写结果 | 把状态和值写入它们来源的那些行 |
| 写入电子表格 | 新建工作簿或工作表，可替换或追加 |
| 向电子表格添加行 | 在最后一行下方添加行，并与表头对应 |
| 填写模板 | 填写模板的单元格或命名单元格，另存为副本 |
| 转换电子表格 | 把工作表转换为 CSV（UTF-8 或 Shift_JIS）、JSON 或 JSON Lines |
| 添加、复制、重命名或删除工作表 | 从模板工作表开始新的一个月，可放心重复运行 |
| 描述工作簿 | 为后续步骤提供工作表、表头和类型 |
| 读取表单 | 从以表单形式排布的报价或订单中读取字段，无论其版式如何 |

在步骤中选择 **工作簿** 后，其中的工作表会以标签页形式显示，前 20 行会按该步骤的读取方式转换后显示，并标出检测到的表格和表头行。

**检查** 会在你运行任何内容之前，向引擎确认该步骤在这台电脑上是否会失败，例如缺少工作簿、工作表或列。回答中的每个单元格地址都是一个按钮，点击即可显示该单元格。

**测试** 会以表格形式显示读取的行。执行写入的步骤在测试期间只报告它会更改什么，除非你勾选 **测试期间保存文件**。转换电子表格是例外：测试它时会真正写出输出文件。

后续步骤要引用的列，需要一个由普通字母组成的简短名称，例如为“Invoice No”取名 `invoice`。可在 **读取电子表格** 中每列旁边的 **后续步骤使用的名称** 里填写，编辑器也会给出建议。

每个执行写入的步骤都有三项设置：**试运行** 只报告更改而不保存；一段最长数分钟的等待时间，在此期间如果工作簿在 Excel 中打开，会先重试，超时后步骤才失败；以及默认开启的通过临时文件保存，确保不会留下写了一半的工作簿。

## 用步骤完成同样的工作

当工作簿只是更大工作流的一部分时，可以用步骤而不是已链接的表格来搭建发票工作：

1. **读取电子表格** 读取 Invoices 工作表。在 **仅限满足条件的行…** 下，选择 Status 列并将值留空，这样就只会读取尚未处理的发票。
2. **逐项处理** 逐行处理这些行。
3. 在循环中放置在门户上登记发票的步骤：[网站步骤](/zh/docs/browser/)、[桌面步骤](/zh/docs/desktop/)或命令。它会产生回执编号。
4. 仍在循环中，**回写结果** 会在该发票所在的行中，把 `Done` 写入 Status，把回执编号写入 Receipt No。

由于写回位于循环之内，失败的行的 Status 会保持为空，下一次运行会再次处理它。无论中间放了什么步骤，电子表格步骤都不使用屏幕。

## 表单，而非表格

以表单形式排布的报价或订单（标签和值分散在工作表各处，而不是在表头下按行排列），由 **读取表单** 读取。

在 **此表单是什么，以及要查找的内容** 下，说明这是一份什么表单。在 **要查找的字段** 下，用工作表本身的语言写明每个字段的名称、类型，以及它的标签在工作表上的样子。

模型会回答每个字段所在的单元格，然后由引擎自己从这些单元格读取值，因此不会凭空编造任何值。

关闭 **将单元格的值发送给模型** 后，模型只能看到每个单元格中是哪类内容，金额和日期都会留在这台电脑上。

**记住此版式，相同的表单无需模型即可读取** 默认开启，因此同一个模板不会再产生模型调用。**忘记已记住的单元格** 会让下一次运行重新询问模型；当表单的版式发生变化，或某个字段从错误的单元格读取时，请使用它。

## 隐私

- 工作簿由 Kitewell 在这台电脑上读取。文件从不上传，其路径也从不离开这台设备。
- **从此文件设置** 会请助手根据打开的工作簿搭建工作流。它会发送列名、每列中识别出的类型以及前 10 行，每个单元格截断为一行。**只发送列名** 则只发送列名。
- 带密码的工作簿只在这台电脑上打开。密码以[密钥](/zh/docs/secrets/)引用的形式保存在 **密码（以密钥引用的形式）** 中，从不写入工作流，也从不记录到日志中。受保护的工作簿无法预览，而且在 Excel 中移除密码之前完全无法导入。
- [与 Dagu Cloud 同步](/zh/docs/cloud-sync/)的链接会携带文件名、工作表、哪台设备持有该文件以及列的对应关系，从不包含路径。表格的行会随之同步，其中包含从工作簿读取的单元格值。
- 文件路径、表格中每一行来自 Excel 的哪一行、从运行中读取的结果，以及为撤销而保留的副本，都留在运行该表格的设备上。不过，[工作区备份](/zh/docs/backups/)会包含这些副本。

完整情况请参阅[哪些数据会离开你的电脑](/zh/docs/data-flow/)。

## 限制

- 支持 `.xlsx` 和 `.xlsm`。`.xls` 或 `.ods` 文件需要先在 Excel 中另存为 `.xlsx`。
- 一次读取最多 5,000 行、约 900 KB。超出任一限制时，步骤会说明保留了哪些内容，并请你缩小范围、减少列或设置行筛选条件。
- 一个表格最多 5,000 行和 30 个结果列，一个循环最多处理 1,000 项。导入的文件最大为 16 MiB。
- 已链接工作簿中的隐藏行会和其他行一起被读取。只有导入的文件才提供排除隐藏行的选项。
- 文件中已有的图表、数据透视表、条件格式和数据验证规则会被保留，但不会新建这些内容，数据透视表也不会刷新。在 Windows 上，宏步骤可以刷新数据透视表。
- 暂不支持 Google 表格。

操作网站或桌面应用的步骤仍然需要相应的应用，因此只有电子表格步骤可以不使用屏幕。
