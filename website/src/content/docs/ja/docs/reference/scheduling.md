[スケジュールとバックグラウンド動作](/ja/docs/scheduling/)に書ききれなかった、スケジュールに関するすべてです。

## 判定の意味

スケジュールのあるワークフローには、5 つの判定のいずれかが付きます。**ワークフロー** の一覧では次回の開始時刻の下に、スケジュールエディターでは予定の下に表示されます。

- **実行されます**、Windows のサービスがオンのときは **サインインの有無にかかわらず実行されます**: 妨げるものはありません。そのあとに続く注意書き（デバイスがバッテリー駆動中など）は、知っておくべきことです。
- **サインイン中のみ実行されます**: 実行されますが、誰かがサインインして Kitewell を開いている間だけです。Windows ではサービスがオフの間がそうで、デスクトップのステップやブラウザーのウィンドウを表示するワークフローはオンでもそうです。
- **実行されません**: 何かが妨げています。理由と直し方が続きます。
- **一時停止中**: ワークフローのスケジュールが一時停止されています。
- **手動実行のみ**: ワークフローにスケジュールがありません。

判定が挙げる理由は、重いものから順に次のとおりです。

- サインインサービスがエンジンを起動できない: パスワードの拒否や未保存、アカウントのロック・無効化・期限切れ、バッチジョブとしてログオンする権利の拒否。
- プロジェクトが一時停止中、またはエンジンかスケジューラーが動いていない。
- ワークフローが保留中、またはスケジュールが読めない。
- パスワードの期限が近い。
- 電源プランがウェイクタイマーを許可しない。
- デバイスがバッテリー駆動中。
- ブラウザーのサインインにあなたのパスワードが必要。
- スケジュールのタイムゾーンがデバイスと異なる。

それぞれの理由には直し方が 1 つあり、理由が表示される場所にボタンとして置かれます。サービスをオンにする、パスワードを更新または追加する、IT 部門向けの文面をコピーする、プロジェクトを再開する、エンジンを起動または再起動する、ワークフローやスケジュールを編集する、デバイス設定を開く、のいずれかです。

判定は、変更から 1 分以内に見直されます。ワークフローの保存やエンジンの起動・停止の直後にも見直されます。

## 最初のスケジュール

デバイスでワークフローに初めて有効なスケジュールが付いたとき、**ワークフロー** の一覧の上にカードが 1 度だけ表示されます。判定と **今すぐスケジュールを試す** が添えられ、**わかりました** で閉じられます。

## 今すぐスケジュールを試す

スケジュール実行と同じキュー、同じ規則でワークフローを 1 回実行し、その実行を開きます。実行は **スケジュールテスト** として一覧に表示されます。取りこぼした予定時刻の代わりになることはありません。

## Windows のサインインサービス

**誰もサインインしていないときに実行** がオンのとき、「Kitewell sign-in」という Windows サービスが PC の起動時に実行アカウントとしてエンジンを起動し、動かし続けます。これには Kitewell Team かトライアルが必要です。Kitewell Personal では、スケジュールはあなたがサインインしている間だけ実行されます。

実行アカウントは、あなた（Windows のタスク スケジューラがパスワードを保存しないタスクを実行するのと同じ方法で、パスワードなしでサインイン）、Windows Server では Kitewell が作成するローカルアカウント `Kitewell Runner`、または指定した別のアカウント（そのパスワード付き）です。

これで得られること:

- 再起動後、誰かがサインインする前にスケジュールが実行されます。
- 予定された実行の 5 分前から 2 分後まで PC はスリープせず、電源プランがウェイクタイマーを許可していれば、次の実行の 1 分前に復帰するタイマーが設定されます。
- サインインするとエンジンがあなたのセッションに移り、デスクトップのステップが画面に届きます。サインアウトすると元に戻ります。

しないこと:

- 誰もサインインしていない間に、デスクトップのステップやブラウザーのウィンドウに画面を与えること。それらのワークフローは **サインイン中のみ実行されます** と表示されます。
- **自分のパスワードを使う…** でパスワードを追加するまで、ネットワーク共有や、Windows があなたのパスワードで保護するサインインに届くこと。必要なワークフローは判定が名指しします。
- ファイルの置き場所を変えること。実行は今までどおり、あなたのフォルダーと設定であなたとして行われます。

Setup.exe は管理者の確認なしに、あなたのアカウント向けに Kitewell をインストールするので、サービスは設定しません。アプリが開いたら **デバイス設定 → 誰もサインインしていないときに実行** でオンにしてください。確認が拒否された場合や設定が途中で止まった場合はそのことが記録され、デバイスのカードがそう伝えてもう一度提案します。

更新のあとは、署名された Kitewell が確認なしに、サービス側のプログラムを新しいバージョンに自分で更新します。

サービスのプログラムは `C:\Program Files\Kitewell` に、データは `C:\ProgramData\Kitewell` に置かれ、データはあなたのデータフォルダーから 1 度だけそこへ移されます。機能をオフにするとサービスは削除され、データはそのまま残ります。

起動、停止、サインインの拒否、設定はすべて、イベント ビューアーのソース **Kitewell sign-in** に記録されます。追加したパスワードは、Windows がサービスのパスワードを保管するのと同じ保護されたストアに置かれ、Kitewell のファイルには書かれません。

## 未実行の予定

実行されないまま過ぎた予定時刻は、次の 4 つの理由のいずれかとともに記録されます。

| 表示される理由 | 何が起きたか |
| --- | --- |
| デバイスがスリープしていました | コンピューターがその時刻にスリープしていた |
| Kitewell が動いていませんでした | Kitewell、Windows ではサービスが動いていなかった |
| プロジェクトのエンジンが動いていませんでした | プロジェクトが一時停止中か、エンジンが止まっていた |
| 実行が開始されませんでした | すべて動いていたのに、エンジンが開始しなかった |

最初の 3 つはデバイス側の、最後はワークフロー側の問題です。**実行とログ** では、**未実行** の行が予定時刻の位置に実行と並んで表示され、**未実行** のタブでそれだけを一覧できます。

行には **キャッチアップがオンのため、エンジンは可能になり次第実行します**、**キャッチアップがオフのため、後で実行されることはありません**、または **(時刻) の実行で追いつきました** のいずれかが示され、最後のものはその実行を開きます。未実行の行は再試行も削除もできず、実行履歴とともに古くなって消えます。

Windows では、しばらく離れたあとのサインイン時に表示される 1 行がその件数を含みます。「12 件の実行、1 件失敗。予定された実行 2 件が開始されませんでした」のように表示されます。

## 取りこぼしの実行

取りこぼしの実行は、コンピューターが戻ったあとに逃した開始を実行します。1 つのワークフローの設定は **スケジュール → 取りこぼしたスケジュール** で変更します。

- **取りこぼしたスケジュールを実行**: **プロジェクトの既定に従う**、**オフ**、**さかのぼる期間を指定** から選びます。
- **さかのぼる期間**: どこまでさかのぼるか。最大 30 日、既定は 24 時間です。
- **取りこぼし時の動作**: **取りこぼした回をすべて実行**、**取りこぼした最新の回のみ実行**、**実行中はスキップ** から選びます。

**プロジェクト設定 → ワークフローの既定値** でプロジェクト全体の既定を決められます。**デバイス設定 → ワークフローの既定値** は新しいプロジェクトの初期値だけを決めます。保持されるのはワークフローごとに最大 1,000 件です。

Kitewell Personal と Team では、[スケジュールの取りこぼしのアラート](/ja/docs/alerts/)で、開始されなかった実行の件数と理由がわかります。

## 複数のスケジュール、一時停止、Webhook

1 つのワークフローに複数のスケジュールを持たせたり、指定の時刻に停止・再起動させたりできます。それらは **追加のスケジュール** にあります。**ワークフロー** の一覧の **スケジュールを一時停止** で、1 つのワークフローを対象から外せます。ワークスペースからダウンロードしたプロジェクトは、ワークフローが一時停止の状態で届きます。

別のサービスからリクエストが届いたときに実行を始めることもできます。**スケジュール** の画面で **Webhook** をオンにします。リクエストが運ぶものは[Webhook でワークフローを開始する](/ja/docs/webhooks/)を参照してください。

Webhook のアドレスは `https://hooks.kitewell.app/…` という形です。リクエストは POST である必要があり、応答は `202` です。ステップは本文を `$WEBHOOK_PAYLOAD`、ヘッダーを `$WEBHOOK_HEADERS` から読みます。

受け付けるのは 1 分あたり約 60 リクエスト、本文 512 KiB、ヘッダー 16 KiB までで、直近 20 件が **最近のリクエスト** に残ります。Windows では、本文がおよそ 32,000 文字を超えると、コマンドラインの長さの制限により実行が始まらないことがあります。

## キュー

キューは、すべてが一度に始まるのを防ぎます。どのプロジェクトにも、同時に 5 件まで実行する **default** キューがあります。変更やキューの追加は **その他 → キュー** で **同時実行数** を指定して行います。ワークフローは **設定** でキューを選びます。

キューは手動の開始、取りこぼしの実行、リトライ、Webhook による実行、スケジュールテスト、[バッチ](/ja/docs/batches/)の行の実行ペースを調整します。スケジュールどおりの時刻に始まる実行は待たされません。プロジェクトで定義されていないキューは、同時に 1 件ずつ実行します。

## 無人で動かす前に

- コマンドは実行アカウントの権限で実行されます。
- Docker のステップには、起動中の Docker が必要です。
- AI のステップには、このデバイスで設定したモデルまたはエージェントが必要です。
- 別のマシンで実行するステップには、接続できるマシンと、承認済みのホスト鍵が必要です。
- [Web サイトのステップ](/ja/docs/browser/)には、Chrome と、成功した **ブラウザーを確認** が必要です。
- このデバイスに値のないシークレットを使う実行は、開始時に失敗します。

## メニュー項目

メニューバーと通知領域の項目は、Kitewell を表示している言語で並びます。**Kitewell を開く**、**Kitewell を終了**、**ワークフローの実行中はスリープしない**、そして Mac では **ログイン時に開く**、Windows では **サインイン時に起動** です。Mac には **メニューバーで実行を続ける** もあり、Windows でサービスがオンのときは **バックグラウンドサービスを更新…** が加わります。

どちらのメニューにもプロジェクトが一覧表示され、プロジェクトごとに開始と停止ができます。Mac では **Kitewell を終了** はすべてを停止し、実行中の処理があれば先に警告します。Windows でサービスがオンのときは、ウィンドウを閉じ、エンジンとその実行はサービスに任せます。

## 詳細

- 実行履歴は、はじめは 30 日間保持されます。**デバイス設定 → 実行履歴の保存期間** で変更できます。[実行とログ](/ja/docs/runs/)を参照してください。
- Mac のスリープ防止（**デバイス設定 → スリープ防止**）は、作業が動いている間コンピューターをスリープさせません。初期設定はオフで、まだ始まっていない予定のためにコンピューターを起こすことはありません。
- Windows のサービスは `kitewell-signin.exe` で、`KitewellSignin` として登録されています。`sc query KitewellSignin` で状態を確認できます。設定のログは `%LOCALAPPDATA%\Kitewell\logs\signin-setup.log` です。
