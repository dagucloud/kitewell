---
title: メールを自動化
---

メールのステップは、このコンピューターで接続したメールボックスのメールを検索し、整理し、送信します。Gmail と Google Workspace、Microsoft 365 と Outlook.com、iCloud、Yahoo、Fastmail、そして任意の IMAP メールボックスに対応します。ワークフローはメールボックスをアドレスで指定し、サインインはデバイスに残ります。

ワークフローのほかのステップと組み合わせれば、受信トレイで始まる仕事も終わる仕事も扱えます。

- 未読の請求書メールごとに添付ファイルを保存し、金額を記録する。
- サポートの依頼を、インポートした API でチケットにする。
- 直近 24 時間に届いたメールを要約し、ダイジェストを送る。
- 届いたメールをフォルダーに振り分ける。行き先はモデルが選ぶ。
- 依頼ごとに返信の下書きを作り、あなたが承認してから送る。

メールのステップはすべてのプランで使えます。

## メールボックスを接続する

プロジェクトの **メールアカウント** を開くか、メールのタスクの **メールボックス** で **メールボックスを接続…** を選び、アドレスを入力します。Kitewell はドメイン、または独自ドメインのメールの届く先からプロバイダーを判別します。間違っていれば **プロバイダーを選ぶ** で直せます。

| プロバイダー | 接続方法 |
| --- | --- |
| Gmail、Google Workspace | Google の審査中はアプリパスワード。審査後はブラウザーでサインイン |
| Microsoft 365、Outlook.com | ブラウザーでサインイン |
| iCloud、Yahoo、Fastmail | プロバイダーのサイトで作るアプリパスワード（ダイアログからリンクされます）。サーバーは自動で入力されます |
| その他のメールボックス | IMAP と SMTP のホスト、ポート、暗号化、ユーザー名、パスワード |

ブラウザーでのサインインでは、プロバイダーのページがブラウザーで開き、あなたが承認するとダイアログが自動で先に進みます。続いて Kitewell が一度サインインしてフォルダーを取得し、受信トレイの未読数、またはサインインに失敗した理由を表示します。この確認が通るまで何も保存されません。

プロバイダーごとの注意点：

- **Google** は、Kitewell の Gmail アクセスの審査を終えるまで、ほとんどのアカウントで Kitewell のブラウザーでのサインインをブロックします。そのページには「このアプリはブロックされます」と表示され、先に進む方法はありません。それまでは、ダイアログは Gmail のメールボックスをアプリパスワードから始めます。2 段階認証プロセスをオンにし、Kitewell という名前でアプリパスワードを作って貼り付けてください。ブラウザーでサインインできる場合は、入力したアドレスと同じアカウントでサインインし、Gmail のチェックボックスをオンにしてください。サードパーティアプリを制限している Google Workspace の管理者は、**API の制御** で Kitewell を許可する必要があります。
- **Microsoft 365** のメールボックスでは、IMAP と認証済み SMTP が有効になっている必要があります。管理者が Microsoft 365 管理センターの、そのユーザーの **メール → メールアプリの管理** で設定します。承認済みのアプリしか許可しない組織では、管理者が Kitewell を一度承認するためのリンクが表示されます。共有メールボックスは、それを開けるメンバーとしてサインインすると接続できます。
- **アプリパスワード**はプロバイダーのサイトで作り、そこで取り消せます。

Kitewell はコンピューターが起動している間ブラウザーでのサインインを更新するので、接続はプロバイダーが終了させるまで続きます。サインインが無効になったメールボックスには、メールアカウント、概要、失敗した実行の横に **再接続** が表示されます。

## 最初のメールのワークフローを作る

この例では、サポートの受信トレイの未読メールを探し、それぞれについてインポートした API でチケットを作り、チケットができたメールを既読にします。

1. ジョブを作成し、タスクの選択肢から **メールを検索** を追加します。メールボックスを選び、**フォルダー** は受信トレイ、**未読のみ** はオンのままにして、ステップに `find` などの ID を付けます。**テスト** で該当するメールを確認できます。
2. **メールごとに…** をオンにします。Kitewell は見つけたメールごとのループを追加し、その最後に現在のメールを既読にする **メールを整理** タスクを置きます。
3. ループの中、そのタスクの前に、チケットシステムの「Create issue」操作で **API アクションを使う** を追加します。フィールドでは、変数の選択肢に現在のメールの差出人、件名、日付、本文が並びます。
4. 5 分ごとなどの[スケジュール](/ja/docs/scheduling/)を追加します。

同じワークフローを YAML で書くと次のようになります。

```yaml
type: graph
steps:
  - id: find
    name: 未読の依頼を探す
    action: mail.search
    with:
      mailbox: support@example.com
      unread: true
  - id: each
    name: 依頼ごとに処理する
    depends: [find]
    foreach:
      items: ${steps.find.outputs.messages}
      as: email
      key: ${foreach.email.id}
      steps:
        - id: ticket
          name: チケットを作る
          action: api.request
          # インポートした「Create issue」操作に、メールのフィールドを渡す
        - id: done
          name: 処理済みにする
          depends: [ticket]
          action: mail.organize
          with:
            mailbox: support@example.com
            emails: ${foreach.email.id}
            mark: read
```

## 各ステップの働き

- **メールを検索** は、フォルダー内の該当するメールを古い順に、差出人、件名、日付、本文とともに一覧にします。既読・未読、差出人、件名、経過時間、添付ファイルで絞り込めます。**添付ファイルを実行のファイルに保存** で、ファイルが実行の成果物に保存されます。1 回の実行で最大 50 件、既定は 20 件なので、たまったメールも順番に消化されます。検索でメールが既読になることはありません。後続のステップは一覧を `${steps.<id>.outputs.messages}` として読めます。
- **メールを整理** は、メールを既読、未読、フラグあり、フラグなしにし、フォルダーへ移動（なければ作成）、アーカイブ、またはゴミ箱へ移します。完全に削除されることはありません。項目ごとに移動先を持てるので、モデルが `[{"id": "…", "move_to": "Invoices"}, …]` と答えれば、1 つのタスクですべてのメールを振り分けられます。**テスト** は変更を予告するだけです。
- **メールを送信** は、メールボックスから添付ファイル付きで送ります。見つけたメールのループの中では、**現在のメールに返信** でそのメールのスレッドに、差出人宛てに `Re:` と元の件名で返信します。Gmail と Microsoft 365 は送信済みに控えを残しますが、ほかのプロバイダーでは残らないことがあります。

## 各メールを一度だけ処理する

**未読のみ** をオンのままにし、各メールの処理が終わったら、ループの中でそのメールのタスクの直後に既読にするか移動します。失敗したメールは未読のまま残るので、次の実行ではそのメールだけが再試行されます。ループの後でまとめて既読にすると、1 件でも失敗したときにどのメールも未読のまま残り、次の実行でほかのメールの処理も繰り返されます。ダイジェストのように一括で扱う仕事なら、最後に **メールを整理** を 1 つ置くのが正解です。

**確認して実行** は、見つけたメールに印が付かないとき、ループの後でしか印が付かないとき、メールの本文がコマンドやコマンドを実行する AI エージェントに渡るときに警告します。その本文はメールの送信者が自由に書けるからです。メールを読むモデルには、ツールを持たない **モデルに尋ねる** タスクを使ってください。

## チームで使う

メールボックスのアドレスは、ほかの文字列と同じようにワークフローの中を移動しますが、接続は移動しません。同僚や [Dagu Cloud](/ja/docs/cloud-sync/) から届いたプロジェクトは、接続すべきメールボックスを概要に表示し、必要な接続ができるまで実行を受け付けません。メールボックスを使うワークフローは 1 台のコンピューターだけで有効にしてください。2 台で動かすと同じメールを処理してしまいます。

## プライバシー

接続とその認証情報はこのコンピューターにとどまり、バックアップ、エクスポート、同期には含まれません。復元したデバイスでは、もう一度接続を求められます。ステップが読んだメールの本文は、実行の保持期間の間このコンピューターに実行と一緒に保存され、AI タスクで選んだモデルなど、ワークフローが送る先にしか出ていきません。Gmail にブラウザーでサインインすると、メールの読み取り、ラベル付け、ゴミ箱への移動、送信の権限（`gmail.modify`）を求めますが、メールを完全に削除する権限は求めません。同意画面と[プライバシーポリシー](/ja/privacy/)にその旨を記載しています。アプリパスワードでは、IMAP と SMTP でメールボックス全体にアクセスできます。

## 制限

- メールを検索 1 回につき最大 50 件です。
- 転送、下書き、メールごとのトリガーはまだありません。**未読のみ** とスケジュールで同じことができます。
- IMAP または認証済み SMTP を無効にしている Microsoft 365 テナントは接続できません。

サインインが無効になったときは、[トラブルシューティング](/ja/docs/troubleshooting/#a-mailbox-needs-reconnecting)を参照してください。
