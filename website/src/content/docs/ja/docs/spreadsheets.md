---
title: Excel を自動化
---

スプレッドシートのステップは、このコンピューターにある `.xlsx` と `.xlsm` のブックを読み、検査し、書き込み、テンプレートに差し込みます。ファイルを直接開くので、Excel は起動せず、ウィンドウも出ず、画面を占有しません。夜間に画面がロックされていても止まらず、Excel のプロセスが残ることもありません。

現場にあるブックをそのまま読めます。表の上のタイトル行、2 行にまたがる結合ヘッダー、途中の小計、下にある注記、全角数字、和暦の日付、先頭のゼロが残る郵便番号。表がどこにあり、各列が何を持つかは Kitewell が判断します。ロボットのためにファイルを作り直す必要はありません。

ブックで始まり、ブックで終わる仕事に向いています。

- 受注一覧の各行を取引先ポータルに登録し、受付番号をその行に書き戻す。
- メールで届いたブックを検査し、データベースに取り込み、件数を返信する。
- 毎月の請求書をテンプレートから作成して送る。
- 商品マスタ.xlsx から商品コードで単価を引き、各行に付ける。
- フォルダー内の各拠点のブックを 1 つの一覧にまとめる。
- レイアウトがばらばらな見積書のフォルダーを、1 つの表に読み取る。
- 毎朝、共有の受注一覧に増えた行だけを処理し、済の印を付ける。

スプレッドシートのステップはすべてのプランで使えます。

## ブックの使い方は 2 通り

**ワークフローのステップとして。** タスクの選択画面の **スプレッドシート** のグループからタスクを追加し、ファイルのパスを指定すると、ワークフローの実行時に読み書きします。ブックが大きな仕事の一部であるときや、[スケジュール](/ja/docs/scheduling/)で動かすときに向いています。

**シートの元データとして。** **新規 → スプレッドシートから**、または `.xlsx` ファイルを Kitewell のウィンドウにドロップすると、Kitewell が行を読み取り、ワークフローを 1 行につき 1 回実行し、結果を元の行に書き戻します。ブックそのものが仕事（片付けるべき一覧）であるときに向いています。進捗、失敗した行だけの再実行、アラートといったシートの動きは[シートでワークフローを一括実行](/ja/docs/batches/)で説明しています。

## ブックをリンクして実行する

1. **新規 → スプレッドシートから** でファイルを選びます。`.xlsx` や `.xlsm` をウィンドウのどこにドロップしても同じです。
2. Kitewell が読み取った内容を表示します。検出した表、実行される行数、そして実行されない行が理由別の件数で示されます。タイトル行、小計、合計、空行、下の注記は除外されます。**表示** で一覧できます。表の範囲がずれていれば、グリッドをドラッグして直せます。
3. 変換できないセルは強調表示されます。たとえば数量に「十二」と入っている行です。**Excel で開く** でファイルを開き、直したら **再確認** で読み直します。
4. グリッドの下に、各行で何をするかを普通の言葉で書きます。「取引先ポータルで受注を登録して、受付番号を控える」のように書くと、アシスタントがワークフローとシートをまとめて提案し、1 枚のカードとして **適用** できます。**保存済みのワークフローを使う** で既存のものを選ぶこともできます。
5. **最初の 1 行を試す** で 1 行目だけを実行します。意図どおりなら **残りの 244 行を実行** で続きを始めます。

結果が出ていて、変更される列にあなたが一度同意するまで、ブックには何も書き込まれません。

## 結果は自分のファイルに戻る

書き込みの前に、結果を入れる列を提示します。各列は編集でき、名前を空にすればその列は書き込まれません。

| 列 | 入るもの |
| --- | --- |
| 状態 | 済、一部失敗、失敗。シートのヘッダーの言語に合わせます |
| 結果ごとに 1 列 | 受付番号など、ワークフローが作った値 |
| エラー | 失敗した理由を 1 行で |
| 実行日時 | その行を最後に実行した時刻 |

同じ名前の列がシートにあればそれを使い、新しい名前なら右端に列を追加します。追加した列は隣の列の書式を引き継ぎます。実行 ID や内部キーの列、セルのコメントは追加しません。

- **元に戻す。** Kitewell は書き込みの前に毎回ファイルをコピーするので、シートの **元に戻す** で書き込み前に戻せます。その後ブックを編集していた場合は、編集を捨てずに、`受注一覧 (before undo).xlsx` として横にコピーを置き、元に戻すことは拒否します。コピーはこのコンピューターに残り、シートを削除すると消えます。
- **Excel で開いていても、失敗ではなく待ちます。** シートに「結果の準備ができています。受注一覧.xlsx を Excel で閉じると書き込みます」と表示され、閉じた時点で自動的に書き込みます。**今すぐコピーに保存** を選ぶと、代わりに `受注一覧 (結果).xlsx` を横に作ります。
- **結果が別の行に入ることはありません。** 行は値が重複しない列（受注番号など）で識別し、書き込む直前にそのキーが同じ行にあることを確認します。実行の合間に Excel で並べ替えても絞り込んでも安全です。移動した行は除外して名前を挙げ、ほかの行はすべて書き込みます。

## ブックを読み直す

ディスク上のファイルが変わるとシートがそれを知らせ、**ブックを読み直す** を提示します。「新規 1 件・更新 1 件・シートにない行 1 件」のように報告し、増えた行を追加し、変わったセルでその行を更新し、シートにない行には「一覧から消えた」の印を付け、移動した行は追いかけます。ヘッダー行からキーの列が消えている場合は、読み取りを中止して、なくなった列を名指しします。

## 毎朝の処理

リンクしたシートは[スケジュール](/ja/docs/scheduling/)で実行できます。その際にさらに 2 つを選びます。先にブックを読むかどうかと、**実行する行** — すべての行か、ブックで増えた行と変わった行だけか。後者にすると、実行時刻ごとにファイルを読み、変わった行だけを実行し、結果を書き戻し、何も変わっていなければ実行を開始しません。

これが RPA を導入する典型的な理由そのものです。共有の受注一覧を毎朝処理する仕事を、ロボット用 PC も、見ている人もなしに回せます。リンクしたシートはファイルがあるコンピューターで動くので、スケジュールもそのコンピューターで設定してください。

## ステップの種類

| タスク | 内容 |
| --- | --- |
| スプレッドシートを読む | シートから行を読む。必要な行だけ、各列を文字列・数値・日付として |
| スプレッドシートを検査する | セルに問題があれば、ほかの処理が始まる前に止める |
| 結果を書き戻す | 状態と値を、元の行に書き込む |
| スプレッドシートを書き出す | 新しいブックやシートを作る。置き換えか追記 |
| スプレッドシートに行を追加する | 最終行の下に、ヘッダーに合わせて行を追加する |
| テンプレートに差し込む | テンプレートのセルや名前付きセルを埋め、コピーとして保存する |
| スプレッドシートを変換する | シートを CSV（UTF-8 または Shift_JIS）、JSON、JSON Lines に |
| シートを追加・複製・名前変更・削除 | テンプレートのシートから今月分を作る。再実行しても安全 |
| ブックの内容を調べる | 後続のステップのために、シート、ヘッダー、型を調べる |
| フォームを読む | 見積書や注文書など、フォーム形式のレイアウトから項目を読み取る |

ステップでブックを選ぶと、シートがタブで並び、最初の 20 行がそのステップが読む形に変換されて表示され、検出した表とヘッダー行も示されます。**確認** は、実行する前に、このコンピューターでそのステップが失敗しないか（ブック、シート、列が見つかるか）をエンジンに問い合わせます。**テスト** は読んだ行を表として見せます。書き込み系のステップはテスト中は変更内容を報告するだけで、明示的に有効にしない限り保存はしません。

同じワークフローを YAML で書くと次のようになります。

```yaml
type: graph
steps:
  - id: orders
    name: Read the orders not done yet
    action: xlsx.read
    with:
      path: ~/Documents/受注一覧.xlsx
      sheet: 受注
      columns:
        - 受注番号: order_no
        - 数量: qty
      types:
        数量: integer
      where:
        状態: ""
  - id: each
    name: For each order
    depends: [orders]
    foreach:
      items: ${steps.orders.outputs.rows}
      as: row
      key: ${foreach.row.order_no}
      steps:
        - id: register
          name: Register it on the portal
          action: http.request
          with:
            method: POST
            url: https://portal.example.com/orders
            headers:
              Content-Type: application/json
            body: '{"order_no": "${foreach.row.order_no}", "qty": ${foreach.row.qty}}'
      collect:
        order_no: ${foreach.row.order_no}
        receipt: ${steps.register.outputs.body}
    output: DONE
  - id: write
    name: Write the 受付番号 back
    depends: [each]
    action: xlsx.update_rows
    with:
      path: ~/Documents/受注一覧.xlsx
      sheet: 受注
      rows: ${DONE}
      key: 受注番号
      set:
        受付番号: receipt
        状態:
          value: 済
```

後続のステップから参照する列には ASCII の名前が必要で、上の `columns` がそれを与えています。エディターが名前を提案し、ループが日本語のヘッダーを参照しているとレビューが指摘します。シート上では各行は日本語のヘッダーのままの見出しを保ちます。

API のないポータルなら、上のリクエストの代わりに[Web サイトのステップ](/ja/docs/browser/)を、API も Web もないアプリなら[デスクトップのステップ](/ja/docs/desktop/)を使います。どちらの場合も、その前後のスプレッドシートのステップは画面を使いません。

## 値の読み取り方

セルは一度だけ変換されるので、日付がシリアル値のまま後続のステップに渡ることはありません。

- **数値と日付。** 日付や時刻は ISO 8601 の文字列になります。和暦や、1900 年と 1904 年のどちらの日付システムにも対応します。型を指定した列の文字列は先に解釈します。全角の数字とカンマ、¥ と円、△ と ▲ と括弧を負の値として、2026/10/1、令和8年10月1日、R8.10.1、元年 といった日付も読みます。
- **文字列は文字列のまま。** 先頭のゼロが残るので、郵便番号や社員番号が数値に変わることはありません。書き戻す値もその型のまま書かれ、数値に見える文字列は文字列のままです。Web サイトから取った値が数式になることはありません。
- **数式** はキャッシュされた値を返します（数式そのものを取ることもできます）。`#N/A` などのエラーは空として読み、警告でセルを名指しします。
- **結合セル** は、本文では覆っているすべてのセルに値を繰り返します。列の外にはみ出す結合セルへの書き込みは、推測せずに、解除すべき範囲を示して拒否します。

## 表ではなくフォーム

見積書や注文書のように、ヘッダーの下に行が並ぶのではなく、ラベルと値がシート上に散らばっているものは **フォームを読む** で読み取ります。何のフォームかと、探す項目を指定すると、モデルが各項目のあるセルを答え、値そのものはエンジンがそのセルから読みます。答えられたセルはシートの形ごとに記憶するので、同じテンプレートで次からモデルの呼び出しは発生しません。**記憶したセルを忘れる** を選ぶと、次回またモデルに尋ねます。

## プライバシー

- ブックはこのコンピューターで Kitewell が読みます。ファイルがアップロードされることはなく、パスがデバイスの外に出ることもありません。
- アシスタントにファイルからシートを組ませるときは、列名、その型、最大 10 行を、選んだモデルに送ります。画面にもそう表示されます。**列名だけを送る** を選べば名前だけを送ります。行の中身は Kitewell が読み、モデルは読みません。
- パスワード付きのブックはこのコンピューターでのみ開き、パスワードは[シークレット](/ja/docs/secrets/)の参照として保持し、ログには残しません。
- 元に戻すためのコピーと、シートの各行がブックのどの行から来たかの対応は、このコンピューターに残ります。プロジェクトのエクスポート、バックアップ、[Dagu Cloud](/ja/docs/cloud-sync/) の同期には含まれません。同期されるのはファイル名とどのコンピューターが持っているかだけで、セルの中身は含まれません。

全体像は[このコンピューターから出るもの](/ja/docs/data-flow/)にあります。

## 制限

- 対応するのは `.xlsx` と `.xlsm` です。`.xls` や `.ods` は Excel で先に `.xlsx` として保存してください。
- 1 回の読み取りは 5,000 行、約 900 KB までです。どちらかを超えると、読み取れた分を報告し、範囲を狭めるか、列を減らすか、行を絞るよう求めます。
- 1 つのシートは 5,000 行まで、ループは 1,000 件までです。
- グラフ、ピボットテーブル、条件付き書式、入力規則は、既にあるものはそのまま保たれますが、新しく作ることはできません。ピボットテーブルの更新も行いません。Windows ではマクロを実行するステップで対応できます。
- Google スプレッドシートにはまだ対応していません。

Web サイトやデスクトップアプリを操作するステップはそのアプリを必要とするので、画面を使わずに済むのはスプレッドシートのステップです。

スプレッドシートのステップが失敗したときは[トラブルシューティング](/ja/docs/troubleshooting/#a-spreadsheet-step-fails)を参照してください。
