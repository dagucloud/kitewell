title: Excel を自動化
---

Excel に一覧があるとします。たとえば今月の請求書が 1 行に 1 件。そして各行にやるべきことがあります。取引先ポータルへの登録、会計システムへの入力、単価の照会。Kitewell はブックから行を読み取り、ワークフローを 1 行につき 1 回実行し、それぞれの結果を元の行に書き戻します。終わったら同じファイルを開くと、請求書の横に受付番号が並んでいます。

作業中、画面には何も出ません。Kitewell は `.xlsx` ファイルを直接開くので、Excel は起動せず、夜間に画面がロックされていても止まらず、Excel のプロセスが残ることもありません。

現場にあるブックをそのまま読めます。表の上のタイトル行、2 行にまたがる結合ヘッダー、途中の小計、下にある注記、全角数字、和暦の日付、先頭のゼロが残る郵便番号。表がどこにあり、各列が何を持つかは Kitewell が判断します。ロボットのためにファイルを作り直す必要はありません。

スプレッドシートのステップはすべてのプランで使えます。

## ブックの使い方は 2 通り

シートの行として使う方法。ブックをシートにリンクすると、各行が 1 回の実行になり、その結果が元の行に戻ります。ブックそのものが仕事（片付けるべき一覧）であるときに向いています。このページでは主にこちらを説明します。

ワークフローのステップとして使う方法。タスクの選択画面の **スプレッドシート** のグループからタスクを追加し、ファイルのパスを指定すると、実行のその時点で読み書きします。ブックが大きな仕事の一部であるとき（メールで届いたファイル、テンプレートから作る毎月の請求書）に向いています。下の[スプレッドシートのステップ](#spreadsheet-steps)を参照してください。

## ブックをシートにリンクする

ファイルがあるコンピューターの Kitewell アプリが必要です。リンクはそのデバイス上のファイルを読み書きするため、ブラウザーでは行えません。

1. 1 行につき 1 回実行するワークフローのシートを作ります。作り方は[シートでワークフローを一括実行](/ja/docs/batches/)にあります。
2. シートのツールバーで **取り込む** を選んで **行を取り込む** を開き、**この端末のブックをリンクする** から `.xlsx` または `.xlsm` のファイルを選びます。ファイルを Kitewell のウィンドウにドロップしても同じです。
3. ブック内の **シート** を選び、列名が入っている行を指定します。プレビューの各行に **3 行目を列名にする** が並び、見出しのない一覧には **列名なし** もあります。列名より上の行、空の行、合計行は取り込まず、それぞれ件数が示されます。合計行を含めるチェックと、Excel で非表示の行を除くチェックもあります。
4. 各列をワークフローの入力に対応付けます。入力と名前が一致する列は自動で割り当てられます。
5. **行を見つけ直す基準** で、行を識別する列（請求書番号や受注番号）を選びます。選べるのは値が重複せず空でもない列だけで、ほかは「値が重複または空」として選択できません。**行の位置** も選べますが、その場合は結果を待っている間に並べ替えや行の挿入をしないでください。
6. **ブックに書き戻す内容** で、Kitewell が追加する列を確認します。**状態**、**エラー**、**実行日時**、そして結果列ごとに **結果: 受付番号** が並びます。名前は変更でき、空にするとその列には何も書きません。
7. **リンクして 6 行を追加** を選びます。

![supplier-invoices.xlsx にリンクした「取引先の請求書」シート。各請求書の横に受付番号と「成功」が並んでいます](../../../../assets/docs/ja/excel-linked-sheet.png)

シートにはブックの行とワークフローの入力列が並び、ツールバーには「supplier-invoices.xlsx にリンク」とファイル名が表示されます。あとは通常のシートと同じように行を実行します。入力の型に合わないセル（金額に「十二」など）は残したまま印が付き、その行は直すまで実行されません。

行が終わるまで、ブックには何も書き込まれません。

## 自分のファイルに戻るもの

行が終わると、Kitewell は 30 秒ほどのうちに自動で結果をブックに書き込みます。**結果を今すぐ書き込む** を選べば待ちません。シートに同じ名前の列があればそれを使い、新しい名前なら右端に列を追加します。

| 列 | 入るもの |
| --- | --- |
| 状態 | 済、一部失敗、失敗、中止、却下 |
| エラー | その行が失敗した理由を 1 行で |
| 実行日時 | その行を実行した時刻。`2026-10-01 09:30` の形式 |
| 結果列ごとに 1 列 | 受付番号など、実行が作った値 |

言葉はブックのヘッダーの言語に合わせます。ヘッダーが日本語のシートには 状態・エラー・実行日時 と、済 / 一部失敗 / 失敗 / 中止 / 却下 が入ります。英語のヘッダーなら Status・Error・Run at と Done / Partly failed / Failed / Stopped / Rejected です。実行 ID や内部キーの列、セルのコメントは追加しません。

現場で起きがちなことと、Kitewell の振る舞いは次のとおりです。

- ファイルが Excel で開かれている。失敗にはなりません。シートに「結果の準備ができています。Excel で supplier-invoices.xlsx を閉じると書き込まれます。」と表示され、閉じた時点で自動的に書き込みます。**結果をコピーに保存する** を選ぶと、代わりに `supplier-invoices (results).xlsx` を横に作ります。日本語のファイル名なら `受注一覧 (結果).xlsx` のように「(結果)」が付きます。Excel が保存せずに閉じてロックファイルだけ残した場合は、**開いていません** でそれを片付けられます。
- 誰かがシートを並べ替えた、または絞り込んだ。書き込みの前に Kitewell はファイルを読み直し、各行のキーが同じ場所にあるかを確認します。移動した行は除外して名前を挙げ、ほかの行はすべて書き込みます。キー列を使っていれば、実行の合間の並べ替えや絞り込みは安全です。
- 書き込むべきでない結果が入ってしまった。**元に戻す** でファイルを戻せます。Kitewell は書き込みの前に毎回ブックをコピーし、直近 10 件を保持しています。その後ブックを編集していた場合は、編集を捨てないために元に戻すことを拒否し、現在のファイルを `supplier-invoices (before undo).xlsx` として横に残します。「(before undo)」は、日本語のファイル名でもこのままです。

**リンクを解除** するとつながりが終わります。行はシートに残り、結果はブックに書き戻されなくなります。

## ブックを読み直す

ディスク上のファイルが変わると、シートに「行を読んだ後にブックが変更されました。」と表示され、**ブックをもう一度読む** が提示されます。読み直すと「supplier-invoices.xlsx を読みました: 新規 1 行 · 更新 1 行 · 1 件がシートにありません」のように結果を報告します。増えた行はシートに加わり、変わったセルはその行を更新し、移動した行は追いかけ、ブックにもうない行は削除せず **リストから消えた行** として残します。

ヘッダー行から、行を識別する列や入力が使う列がなくなっている場合は、読み取りを中止して、なくなった列を名指しします。列を選び直すには、ブックをもう一度リンクしてください。

## 毎朝の処理

リンクしたシートは[スケジュール](/ja/docs/scheduling/)で実行できます。その際にさらに 2 つを選びます。**先に supplier-invoices.xlsx を読む** と、**実行する行** — **すべての行** か、**ブックで追加・変更された行だけ** か。後者にすると、実行時刻ごとにファイルを読み、変わった行だけを実行し、結果を書き戻し、何も変わっていなければ実行を開始しません。

これが RPA を導入する典型的な理由そのものです。共有の受注一覧を毎朝処理する仕事を、ロボット用 PC も、見ている人もなしに回せます。リンクしたシートはファイルがあるコンピューターで動くので、スケジュールもそのコンピューターで設定してください。ほかのデバイスでのスケジュール設定は拒否され、別のデバイスで実行時刻が来た場合は、どのデバイスにファイルがあるかを示してスキップします。

## スプレッドシートのステップ

ワークフローの中では、タスクの選択画面の **スプレッドシート** のグループに 10 個のタスクがあります。

| タスク | 内容 |
| --- | --- |
| スプレッドシートを読む | シートの行を、必要な行だけ、各列を文字・数値・日付として読み取ります |
| スプレッドシートを検査する | セルに誤りがあれば、何かが起きる前に止めます |
| 結果を書き戻す | 状態や値を、元の行に書き込みます |
| スプレッドシートを書き出す | 新しいブックやシートを作成、置き換え、または追記します |
| スプレッドシートに行を追加する | 最後の行の下に、見出しに合わせて行を追加します |
| テンプレートに記入する | テンプレートのセルや名前付きセルに記入し、コピーとして保存します |
| スプレッドシートを変換する | シートを CSV（UTF-8 または Shift_JIS）、JSON、JSON Lines に変換します |
| シートの追加・コピー・名前変更・削除 | テンプレートのシートから月を始めます。再実行しても安全です |
| ブックの構成を調べる | 後のステップのために、シート・見出し・型を調べます |
| フォームを読む | 見積や注文など、フォーム形式のシートから項目を読み取ります。レイアウトは問いません |

ステップで **ブック** を選ぶと、シートがタブで並び、最初の 20 行がそのステップが読む形に変換されて表示され、検出した表とヘッダー行も示されます。

**チェック** は、実行する前に、このコンピューターでそのステップが失敗しないか（ブック、シート、列が見つかるか）をエンジンに問い合わせます。答えに出てくるセル番地はボタンになっていて、そのセルを表示できます。**テスト** は読んだ行を表として見せます。書き込み系のステップはテスト中は変更内容を報告するだけで、**テスト中もファイルを保存する** にチェックしない限り保存しません。例外は「スプレッドシートを変換する」で、テストでも出力ファイルを実際に書き出します。

## 表ではなくフォーム

見積書や注文書のように、ヘッダーの下に行が並ぶのではなく、ラベルと値がシート上に散らばっているものは **フォームを読む** で読み取ります。**このフォームの内容と、見つけたい項目** に何のフォームかを書き、**見つける項目** に各項目の名前、型、シート上でのラベルの見え方を、シートの言語で書きます。

モデルが各項目のあるセルを答え、値そのものはエンジンがそのセルから読み取るので、値が捏造されることはありません。**セルの値をモデルに送る** をオフにすると、モデルには各セルの種類しか見えなくなり、金額や日付はこのコンピューターに留まります。

**このレイアウトを記憶し、同じフォームはモデルなしで読む** は既定でオンなので、同じテンプレートで次からモデルの呼び出しは発生しません。**記憶したセルを忘れる** を選ぶと、次回またモデルに尋ねます。フォームのレイアウトが変わったときや、項目が誤ったセルから読まれたときに使ってください。

## プライバシー

- ブックはこのコンピューターで Kitewell が読みます。ファイルがアップロードされることはなく、パスがデバイスの外に出ることもありません。
- **このファイルから設定する** は、開いているブックからワークフローを組み立てるようアシスタントに依頼します。送るのは列名、各列で見られた型、そして最初の 10 行で、各セルは 1 行に切り詰められます。**列名だけを送る** を選べば名前だけを送ります。その後アシスタントがシートを組むときは、Kitewell が行を読むので、行の中身はモデルを通りません。
- パスワード付きのブックはこのコンピューターでのみ開きます。パスワードは **パスワード（シークレットの参照）** として[シークレット](/ja/docs/secrets/)の参照で保持し、ワークフローには書かれず、ログにも残りません。保護されたブックはプレビューできず、Excel でパスワードを解除するまで取り込みもできません。
- [Dagu Cloud と同期](/ja/docs/cloud-sync/)されるリンク情報は、ファイル名、シート名、どのデバイスが持っているか、列の対応付けで、パスは含まれません。シートの行も一緒に同期され、その行にはブックから読み取ったセルの値が入っています。同期したシートは、その分のファイルの中身を持ち運ぶとお考えください。
- ファイルのパス、シートの各行がブックのどの行から来たか、実行から読み取った結果、元に戻すためのコピーは、シートを実行したデバイスに残ります。例外は[ワークスペースのバックアップ](/ja/docs/backups/)で、これはワークスペース全体の書庫なので、そのコピーも含まれます。

全体像は[このコンピューターから出るもの](/ja/docs/data-flow/)にあります。

## 制限

- 対応するのは `.xlsx` と `.xlsm` です。`.xls` や `.ods` は、Excel で先に `.xlsx` として保存し直してください。
- 1 回の読み取りは 5,000 行、約 900 KB までです。どちらかを超えると、読み取れた分を報告し、範囲を狭めるか、列を減らすか、行を絞るよう求めます。
- 1 つのシートは 5,000 行・結果列 30 列まで、ループは 1,000 件までです。取り込むファイルは 16 MiB までです。
- リンクしたブックの非表示の行は、ほかの行と一緒に読み取られます。除外を選べるのは、ファイルを取り込む場合だけです。
- グラフ、ピボットテーブル、条件付き書式、入力規則は、既にあるものはそのまま保たれますが、新しく作ることはできません。ピボットテーブルの更新も行いません。Windows ではマクロを実行するステップで対応できます。
- Google スプレッドシートにはまだ対応していません。

Web サイトやデスクトップアプリを操作するステップはそのアプリを必要とするので、画面を使わずに済むのはスプレッドシートのステップです。

スプレッドシートのステップが失敗したときは[トラブルシューティング](/ja/docs/troubleshooting/#a-spreadsheet-step-fails)を参照してください。

## 詳細

ブックが大きなワークフローの一部であるときは、リンクしたシートの代わりに、同じ仕事をステップとして組み立てられます。

1. **スプレッドシートを読む** で、`supplier-invoices.xlsx` の「請求書」シートを読みます。**次の条件の行だけ…** で「状態」列を選び、値を空のままにすると、未処理の請求書だけが読まれます。
2. **各項目を処理** で、その行を 1 行ずつ回します。
3. ループの中に、請求書をポータルに登録するステップを置きます。API のないポータルなら [Web サイトのステップ](/ja/docs/browser/)、API も Web もないアプリなら[デスクトップのステップ](/ja/docs/desktop/)、あるいはコマンドです。このステップが受付番号を出します。
4. 同じくループの中の **結果を書き戻す** が、その請求書の行の「状態」に「済」を、「受付番号」に受付番号を書き込みます。

書き戻しがループの中にあるので、失敗した行は「状態」が空のまま残り、次の実行で拾い直されます。

後続のステップから参照する列には、「請求書番号」に対する `invoice` のような、半角英字の短い名前が必要です。**スプレッドシートを読む** の各列にある **後のステップ用の名前** に入力します。エディターが名前を提案し、ループが日本語のヘッダーを参照しているとレビューが指摘します。シート上では各行は日本語のヘッダーのままの見出しを保ちます。

書き込み系のステップには 3 つの設定があります。**ドライラン** は保存せずに変更内容だけを報告します。待ち時間を数分まで指定でき、Excel で開かれているブックはその時間だけ再試行してからステップが失敗します。一時ファイルを経由した保存は既定でオンで、書きかけのブックを残しません。

間にどのステップを置いても、スプレッドシートのステップは画面を使いません。
