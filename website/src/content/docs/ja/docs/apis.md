---
title: API のインポート
---

OpenAPI 仕様書をインポートすると、そのオペレーションをワークフローのステップとして使えます。Kitewell は仕様書から入力フォームを作成し、レスポンスのフィールドを後続のステップで使えるようにします。接続はプロジェクトに属し、そのプロジェクト内のワークフローで再利用できます。

## インポートして接続する

1. プロジェクトのサイドバーで **API ライブラリ** を開き、**API をインポート** を選びます。
2. **ファイルをアップロード**、**URL から**、**仕様書を貼り付け** のいずれかを選びます。JSON または YAML 形式の OpenAPI 3.0 または 3.1 のドキュメントを指定します。
3. **アクションをプレビュー** を選びます。アクション名、パス、タグで検索し、アクションの入力とレスポンスを確認します。サポートされていないアクションには理由が表示されます。
4. **名前**、**API 識別子**、**サーバー URL** を確認します。仕様書にサーバー URL がない場合は入力します。
5. **認証** を選び、必要に応じてプロジェクトのシークレットを接続します。**API を接続** を選んで保存します。

**API 識別子** は、ワークフローがこの接続を見つけるために使う名前です。インポートした仕様書は、URL から取得した場合も含めてプロジェクトに保存されます。API をプレビューまたは接続しても、そのオペレーションは呼び出されません。仕様書の URL に認証が必要な場合は、別途ダウンロードして **ファイルをアップロード** または **仕様書を貼り付け** を使ってください。

## 認証情報を接続する

API の要件に応じて、**認証なし**、**Bearer トークン**、**API キー**、**ユーザー名とパスワード** のいずれかを選びます。API キーの場合は **キー名** を入力し、ヘッダー、クエリパラメーター、Cookie のどれで送信するかを選びます。

同じプロジェクトにある既存の **シークレットの参照**（`services/support-token` など）を選択または入力するか、接続フォームの **新しいシークレットを保存** を使います。

Bearer 認証と API キー認証では、シークレットにトークンまたはキーを格納します。**ユーザー名とパスワード** の場合は、ユーザー名を接続に入力し、パスワードにはシークレットを使います。接続は参照を保存し、それを使うすべての API アクションに認証情報を渡します。認証情報そのものはプロジェクトのシークレットに保持されます。ローテーションとアクセスの詳細は [シークレット](/ja/docs/secrets/)を参照してください。

OAuth によるサインインとトークンの更新には対応していません。OAuth のアクセストークンを受け付ける API では、トークンを別途取得し、Bearer トークンとして接続してください。トークンの有効期限が切れたら、シークレットを置き換えます。

## ワークフローでアクションを使う

1. ワークフローの **組み立て** タブでタスクを追加し、**API アクションを使う** を選びます。
2. **接続済み API** を選び、**API アクションを検索** でオペレーションを選択します。
3. 生成された入力欄に値を入力します。必須フィールドが先に表示されます。必要に応じて **任意のパラメーター** を展開します。オペレーションにリクエスト本文が定義されている場合は、**リクエスト本文** のフォームが表示されます。
4. 入力欄の横にある変数ピッカーを使って、ワークフローの入力や前のステップの値を挿入します。
5. ワークフローをチェックしてから実行し、**実行とログ** で出力を確認します。

**API ライブラリ** で保存済みの接続を開き、アクションを選択して **このアクションでワークフローを作成** を選ぶこともできます。

## レスポンスのフィールドを別のステップに渡す

API ステップの **レスポンスフィールド** を展開すると、仕様書に記述されたフィールドが表示されます。別のステップで入力欄の横にある **変数** を開き、その API レスポンスのフィールドを選びます。Kitewell が出力のマッピングを追加してステップ同士を接続するため、受け取る側のステップは API 呼び出しの完了を待ちます。

たとえば、顧客の検索で返された `id` を、チケットを作成する後続のアクションに渡せます。利用できるフィールドは、インポートした仕様書のレスポンススキーマによって決まります。

## 仕様書を更新する

Kitewell は、置き換えるまでインポート時のスナップショットを保持します。元の URL の内容が変わっても、プロジェクトは自動的には更新されません。

**API ライブラリ** で接続を開き、**仕様書を更新** を選んで、置き換える仕様書をアップロード、取得、または貼り付けます。**アクションをプレビュー** を選んでオペレーションを確認し、**接続設定を保存** を選びます。Kitewell は保存前に、依存するワークフローを検証します。置き換えによって保存済みのワークフローが無効になる場合、更新は拒否され、以前の接続が維持されます。先に影響を受けるワークフローを更新するか、置き換える仕様書を別の API 識別子でインポートしてください。

保存済みのワークフローが使っている接続は、Kitewell で削除することもできません。

## 認証情報を含めずに接続を共有する

[プロジェクトのエクスポート](/ja/docs/sharing/)を使うと、インポートした仕様書と接続設定（サーバー URL、認証の種類、シークレットの参照を含む）を共有できます。管理されているシークレットの値は含まれません。受け取る側のデバイスでは、API アクションを実行する前に、インポートしたプロジェクトで参照先のシークレットを作成するか、そのプロジェクトの別のシークレットを使うように接続を変更してください。

エクスポートには、仕様書とその取得元 URL が含まれます。これらのフィールドやワークフローの入力に直接入力した認証情報は、自動的には削除されません。

## インポートの制限

- インポートできるのは、8 MiB までの JSON または YAML ドキュメント 1 つです。Swagger 2 のドキュメントは、先に OpenAPI 3.0 または 3.1 に変換する必要があります。
- 参照は同じドキュメント内を指している必要があります。外部参照は、インポートする前にバンドルしてください。
- リクエスト本文には JSON、URL エンコードされたフォーム、テキストを使えます。ファイルのアップロードを含むマルチパートの本文と、バイナリのリクエスト本文は、API アクションではサポートされていません。
- 1 つのアクションで複数の認証情報を同時に要求することはできません。サポートされていない認証方式は、アクションの選択画面に表示されます。
- ページネーションは自動では行われません。ページやカーソルの入力を指定し、繰り返しのリクエストをワークフローで制御してください。

同じインポート済みのアクションとスキーマは、[MCP](/ja/docs/mcp/) からも利用できます。
