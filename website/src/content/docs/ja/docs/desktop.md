---
title: デスクトップアプリを自動操作
---

**デスクトップアプリを自動操作** ステップは、コンピューター上のアプリを人と同じようにモデルに使わせます。画面を見て、クリックし、入力します。「%client% の請求書を作成して保存する」のようにタスクを自然な言葉で書くと、モデルは終わるまで作業を続けます。macOS と Windows で、あなた自身の画面上で動くので、API も Web 版もない会計ソフト、ERP のクライアント、表計算アプリにも届きます。

[Web サイトのステップ](/ja/docs/browser/)、[メールのステップ](/ja/docs/email/)、スケジュール、[バッチシート](/ja/docs/batches/)と組み合わせれば、RPA（ロボティック・プロセス・オートメーション）ツールが担ってきたデスクトップ側の作業をこなせます。

- スプレッドシートの各行を、会計ソフトや販売管理アプリに転記する。
- デスクトップのダッシュボードから数値を読み取り、次のステップに渡す。
- メニューからしか書き出せないアプリのレポートをエクスポートする。
- 更新後に、アプリが正しい表示をしているか確かめる。

## 最初の実行の前に

- **コンピューター操作に対応したモデル**：[エージェントとモデル](/ja/docs/ai/)で、提供元がコンピューター操作ツールを備えた API モデル（Claude Sonnet 5、GPT-5.4、Gemini 3.5 以降など）を選ぶか、ワークフローの **設定** で **ブラウザーとデスクトップのステップの既定モデル** を設定します。**デスクトップ設定** の **モデルがデスクトップを操作する方法** は **自動** です。**汎用ツール（どの画像対応モデルでも可）** にすると、コンピューター操作ツールのないモデルでも汎用のクリック・入力ツールで動きますが、遅く、信頼性も下がります。
- **デスクトップへのアクセス**：**デバイス設定 → デスクトップ自動操作** を開き、**デスクトップへのアクセスを確認** を選びます。
  - macOS では、Kitewell のバックグラウンドサービスである **Kitewell Agent** に、画面収録と Mac の制御を許可する必要があります。確認を実行すると macOS が両方の許可を求め、各行から対応するシステム設定のパネルを開けます。
  - Windows では、Kitewell を Windows サービスとしてではなく、サインイン中のセッションで実行する必要があります。管理者として動いているアプリには、Kitewell も管理者として動いていない限り、クリックも入力もできません。
- **ロックされていない画面**で、あなたのユーザーがサインインしていること。デスクトップステップはあなたが見ている画面を使うため、ロック中やスリープ中のコンピューターでは動きません。

## 最初のデスクトップステップを作る

この例では、表計算アプリを開いて顧客の最新の請求書を探し、その番号を次のステップに渡します。

1. ワークフローを作成し、タスクの選択肢から **デスクトップアプリを自動操作** を追加します。ステップに `copy` などの ID を付けます。
2. **モデル** を選びます。
3. **ステップが入力する値** に `client` を追加し、顧客名を設定します。直接入力した文字列、ワークフローの入力、シークレットのいずれかを使えます。
4. **デスクトップでのステップ** に次を追加します。
   - **アプリを開く**：macOS では **アプリを選択…** で Numbers を選びます。Windows では **プログラムを選択…** でプログラムを選びます。
   - **タスクを実行**：`請求書のスプレッドシートを開き、%client% の最新の行を探す`
   - **画面から読み取る**：`その行の請求書番号と合計` を探し、`number` を **テキスト**、`total` を **数値** として読み取ります。
5. **テスト** を選び、マウスとキーボードから手を離して見守ります。
6. `${steps.copy.outputs.number}` を使う後続のステップを追加します。

同じワークフローを YAML で書くと次のようになります。

```yaml
type: graph
llm:
  model: kitewell-agent-fast
params:
  - CLIENT: Acme
steps:
  - id: copy
    name: 最新の請求書を探す
    action: computer.run
    with:
      variables:
        client: ${params.CLIENT}
      do:
        - launch: {command: open, args: [-a, Numbers]}
        - act: 請求書のスプレッドシートを開き、%client% の最新の行を探す
        - extract:
            instruction: その行の請求書番号と合計
            schema:
              type: object
              properties:
                number: {type: string}
                total: {type: number}
  - id: report
    name: 請求書を報告する
    depends: [copy]
    run: echo "${steps.copy.outputs.number}"
```

Windows では、**アプリを開く** にプログラムのパスを指定します（`launch: notepad.exe` など）。引数を渡すには `{command, args}` を使います。

## ステップでできること

操作はあなたの画面上で順番に実行されます。タスクはひとまとまりの仕事でよく、モデルは上限の範囲で必要なだけ操作します。

- **アプリを開く**：アプリやプログラムを起動します。アプリが閉じるのは待ちません。
- **タスクを実行**：**タスク（自然な言葉で）**。`%name%` で、ステップが入力する値や以前の回答を入力します。**デスクトップ設定** の **タスクごとの最大操作数** は、1 つのタスクで行えるクリックと入力の数の上限です。既定は 50 で、タスクごとに個別の上限も設定できます。それより多く必要なタスクは失敗するので、分割するか上限を上げてください。
- **画面から読み取る**：**探すもの** と、**読み取る値** に各値の名前、型、説明を設定します。各値は結果になり、後続のステップが `${steps.<id>.outputs.<name>}` として読めます。
- **次を確認する…**：**画面に表示されているべきもの…** を書きます。表示されていなければステップは失敗します。**確認を続ける時間** で、アプリがその状態になるまで待てます。
- **待つ**：一定時間待ちます。
- **スクリーンショットを撮る**：画面全体を PNG で実行の成果物に保存します。
- **私に入力を求める**：ワンタイムコードなどのために、あなたが答えるまで一時停止します。**回答の名前** で、後の操作から参照する名前を付けます。

**次の場合のみ… と制限時間** で、条件が成り立つときだけ操作を実行し、操作にかけられる時間を設定できます。既定は 5 分です。

## 値とシークレット

**ステップが入力する値** には、指示の中で `%name%` と書いて入力する値を置きます。モデルが見るのは名前だけです。機密性のあるものにはシークレットを選んでください。指示、モデル、ログのどこにも値は出ません。指示にシークレットの値そのものが含まれるステップは、送信せずに失敗します。

## 画面をあなたと共有する

デスクトップステップは、デバイスの 1 つの画面で 1 つずつ実行されます。クリックや入力の前に、マウスとキーボードが 15 秒間使われなくなるまで待ち、あなたが使い始めると一時停止します。あなたの手元から操作を奪うことはありません。**デスクトップ設定** の **マウスやキーボードが使われなくなってから待つ時間** で待ち時間を変えられます。誰も作業しないコンピューターでは無効にもできます。

デスクトップステップの実行中は、メニューバーまたはトレイの Kitewell アイコンが変わり、メニューにステップ名と **ステップを止める** が表示されます。実行画面には各操作とそのスクリーンショットが表示され、デスクトップが空くのを待った時間も分かります。

## 確認が求められたとき

購入などの操作について、モデルの提供元が人の確認を求めた場合、ステップは停止します。**デスクトップ設定** の **モデル提供元が操作の確認を求めたとき** を **続行する** にすることもできますが、より安全なのは、タスクの前に **私に入力を求める** を置いて、あなたが判断することです。

## リプレイ

完了したタスクは記録され、画面の見た目が同じである限り、以降の実行ではモデルに尋ねずに繰り返されます。より速く、費用もかかりません。アプリが変わったときは、**毎回あらためて判断する** で 1 つのタスクのリプレイを無効にするか、**プロジェクト設定 → ストレージ → リプレイキャッシュ** でワークフローの記録を消去します。キャッシュはこのデバイスにとどまり、バックアップには含まれません。

## 費用とプライバシー

モデルが処理する操作ごとに、**ほかに開いているウィンドウも含めた画面全体のスクリーンショット**がモデルの提供元に送られ、提供元の料金がかかります。ステップには使用したトークン数が表示されます。実行前に見られてはいけないものを閉じるか、ほかの人が作業しないコンピューターを使ってください。ステップが入力する値とシークレットは、モデルに送られません。実行と一緒に保存されたスクリーンショットは、実行の保持期間の間このデバイスに残ります。

## 制限

- macOS と Windows のみで、このコンピューター自身の画面を使います。スケジュール実行にはロック解除とスリープ解除が必要です。
- デスクトップステップは同時に 1 つだけ実行されます。2 つ目は 1 つ目の終了を待ちます。
- モデルにはコンピューター操作ツールが必要です。または、汎用ツールとツール呼び出しに対応した画像対応モデルの組み合わせが必要です。小さなローカルモデルでは、通常デスクトップを操作できません。
- 画面収録をブロックするアプリや、Kitewell が管理者でないときに管理者として動く Windows のアプリは操作できません。

ステップが失敗したときは、まずスクリーンショットを確認してください。[トラブルシューティング](/ja/docs/troubleshooting/#a-desktop-step-fails)も参照してください。
