## スケジュールを選ぶ

ワークフローエディターの**スケジュール**では、手動、毎日、平日、毎週、毎時、カスタムのスケジュールを選べます。タイムゾーンを確認して変更を保存し、**保存済みのスケジュールを有効にする**がオンになっていることを確認してください。

## Kitewell を実行したままにする

macOS の場合：

- ウィンドウを閉じるか **Keep Running in Menu Bar**（⌘Q）を選ぶと、サービスとプロジェクトのエンジンを実行したまま、ウィンドウが非表示になります。
- **Open Kitewell** を選ぶと、画面が再び表示されます。
- **Quit Kitewell** を選ぶと、サービスとプロジェクトのエンジンが停止します。実行中の処理がある場合は、警告を表示してから中断します。先に下書きを保存し、実行中のワークフローが終わるのを待ってください。
- **Start at login** をオンにすると、サインイン時に Kitewell がメニューバーで起動します。

Windows の場合：

- ウィンドウを閉じると、サービスとプロジェクトのエンジンを実行したまま、ウィンドウが非表示になります。Kitewell はトレイ（通知領域）に残ります。
- トレイアイコンを左クリックするか、そのメニューで **Open Kitewell** を選ぶと、画面が再び表示されます。
- **Quit Kitewell** を選ぶと、サービスとプロジェクトのエンジンが停止します。実行中の処理がある場合は、警告を表示してから中断します。先に下書きを保存し、実行中のワークフローが終わるのを待ってください。
- **Start at login** をオンにすると、サインイン時に Kitewell がトレイで起動します。

メニューバーのメニューとトレイメニューにはプロジェクトが一覧表示され、プロジェクトごとに開始と停止を操作できます。画面上でプロジェクトを切り替えても、ほかのプロジェクトのスケジュールは止まりません。

## スリープ、ログアウト、取りこぼした実行

コンピューターがスリープしておらず、ユーザーがログインしている必要があります。Kitewell はスリープ中のコンピューターを復帰させません。電源が切れている、スリープしている、またはログアウトしているマシンでは、スケジュールされた時刻に作業を実行できません。**デバイス設定 → スリープ防止**、または macOS ではメニューバーのメニュー、Windows ではトレイメニューにある **Keep awake while workflows run** で、作業の実行中にコンピューターがアイドルスリープに入るのを防げます。この設定は既定でオフです。

既定では、直前の 24 時間に取りこぼしたスケジュールは、コンピューターの復帰後に実行されます。この動作は、プロジェクトでは**プロジェクト設定 → ワークフローの既定値**、ワークフローごとには**スケジュール → 取りこぼしたスケジュール**で変更します。

- 最大 30 日前までさかのぼれます。
- 取りこぼしたすべての回、最新の回だけ、実行中はスキップ、のいずれかを選べます。
- 取りこぼした開始は、ワークフローごとに最大 1,000 件まで保持されます。

**デバイス設定 → ワークフローの既定値**は、新しいプロジェクトの初期値を決めるだけです。取りこぼした実行がすべて復帰後に再実行されるとは限らないので、実際のスケジュールで動作を確認してください。

Kitewell Pro では、[スケジュールの取りこぼしのアラート](/ja/docs/alerts/)で、開始されなかったスケジュール実行の数とその理由がわかります。

## キュー

キューは、同時に実行する数を制限します。どのプロジェクトにも、同時に 5 件まで実行する **default** キューがあります。変更やキューの追加は **その他 → キュー** で行います。ワークフローは設定でキューを選び、プロジェクトで定義されていないキューは同時に 1 件ずつ実行します。

キューは、手動の開始、取りこぼしの実行、リトライ、[バッチ](/ja/docs/batches/)の行の実行ペースを調整し、それぞれ空きを待ちます。スケジュールどおりの時刻に始まる実行は待たされません。バッチシートには、ワークフローのものとは別に、シートで設定する独自のスケジュールがあります。**実行とログ** には、キューごとの実行中と待機中の数が表示され、待機中の実行を取り除けます。

## 実行履歴

Kitewell は、既定で 30 日間の実行履歴を保持します。**デバイス設定 → 実行履歴の保存期間** で変更できます。それより古い実行は、すべてのワークフローについて 1 日 1 回削除されます。自分で実行を削除するには、[実行とログ](/ja/docs/runs/)を参照してください。

## タスクの要件

コマンドは、Kitewell を実行しているユーザーの権限で実行されます。ステップの種類ごとに必要なものがあります。

- **Docker タスク**：実行中の Docker デーモン。
- **AI タスク**：設定したツールまたはプロバイダー。
- **リモートタスク**：接続可能なサーバーと、承認済みの SSH ホストキー。
- **[Web サイトのステップ](/ja/docs/browser/)**：Chrome、成功した **ブラウザーを確認**、そして通常は非表示のブラウザーウィンドウ。

このデバイスに値のないシークレットを使う実行は、開始時に失敗します。無人で実行する作業をスケジュールする前に、これらの前提条件をテストしてください。

ほかの場所からインポートまたはダウンロードしたワークフローは、一時停止の状態で届きます。**概要** で、このデバイスで実行するものを有効にしてください。
