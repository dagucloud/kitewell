## スケジュールを選ぶ

ワークフローエディターの**スケジュール**では、手動、毎日、平日、毎週、毎時、カスタムのスケジュールを選べます。タイムゾーンを確認して変更を保存し、**保存済みのスケジュールを有効にする**がオンになっていることを確認してください。

## Kitewell を実行したままにする

macOS の場合：

- ウィンドウを閉じるか **Keep Running in Menu Bar** を選ぶと、サービスとプロジェクトのエンジンを実行したまま、ウィンドウが非表示になります。
- **Open Kitewell** を選ぶと、画面が再び表示されます。
- **Quit Kitewell** を選ぶと、サービスとプロジェクトのエンジンが停止します。先に下書きを保存し、実行中のジョブが終わるのを待ってください。
- **Start at login** をオンにすると、サインイン時に Kitewell がメニューバーで起動します。

メニューバーにはプロジェクトが一覧表示され、プロジェクトごとに開始と停止を操作できます。画面上でプロジェクトを切り替えても、ほかのプロジェクトのスケジュールは止まりません。

## スリープ、ログアウト、取りこぼした実行

コンピューターがスリープしておらず、ユーザーがログインしている必要があります。Kitewell はスリープ中のコンピューターを復帰させません。電源が切れている、スリープしている、またはログアウトしているマシンでは、スケジュールされた時刻に作業を実行できません。macOS では、**デバイス設定 → スリープ防止**で、作業の実行中にコンピューターがアイドルスリープに入るのを防げます。この設定は既定でオフです。

既定では、直前の 24 時間に取りこぼしたスケジュールは、コンピューターの復帰後に実行されます。この動作は**デバイス設定 → ワークフローの既定値**、**プロジェクト設定 → ワークフローの既定値**、またはワークフローの**スケジュール → 取りこぼしたスケジュール**で変更し、実際のスケジュールで動作を確認してください。取りこぼした実行がすべて、コンピューターの復帰後に再実行されるとは限りません。Kitewell Pro では、[スケジュールの取りこぼしのアラート](/ja/docs/alerts/)で、開始されなかったスケジュール実行の数とその理由がわかります。

## タスクの要件

コマンドは、Kitewell を実行しているユーザーの権限で実行されます。Docker タスクには、実行中の Docker デーモンが必要です。AI タスクには、設定したツールまたはプロバイダーが必要です。リモートタスクには、接続可能なサーバーと、承認済みの SSH ホストキーが必要です。無人で実行する作業をスケジュールする前に、これらの前提条件をテストしてください。
