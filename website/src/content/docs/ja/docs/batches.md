---
title: バッチ
---

バッチは、シートの行ごとに 1 つのワークフローを 1 回ずつ実行します。顧客、物件、ページ、ファイルなど、処理したい項目を行に並べます。各行はその行の入力でワークフローを実行し、結果列には各実行で見つかった値が集まります。

## シートを作る

サイドバーの**その他 → バッチ**を開いて**新しいシート**を選び、ワークフローを選んでシート名を付けます。ワークフローの実行ダイアログから始めることもできます。**単独実行**から**バッチシート**に切り替えると、入力済みの値が新しいシートの共通の入力になります。

シートには、ワークフローのパラメーターごとに 1 つの入力列があり、型、既定値、選べる値もそのまま引き継がれます。**ラベル**は行の名前で、ワークフローには渡されません。ワークフローが宣言していないパラメーターも受け付ける場合は、**その他の入力（JSON）**列でそれらを JSON オブジェクトとして指定します。

1 つのシートには最大 5,000 行、結果列は最大 30 列まで入ります。

## 行を追加する

- **入力または貼り付け**：セルを直接編集するか、スプレッドシートからコピーしたセルを、選択中のセルを起点に貼り付けます。必要に応じて行が追加されます。
- **取り込む**：Excel ブック（`.xlsx` または `.xlsm`）か CSV ファイルを選ぶか、シートのどこかにドロップするか、セルや 1 行 1 値のテキストを貼り付けます。プレビューには先頭の行が表示され、列名がある行は自動で選ばれます。別の行や「列名なし」も選べます。入力の名前や表示名と一致する列は自動で割り当てられ、列名があるときはそれ以外の列はスキップされます。どの列も、入力、**ラベル**、または**列をスキップ**に割り当て直せます。列名より上の行、空の行、合計や小計などの合計行は取り込まず、合計行を含めることもできます。ブックは Excel で開いたときのシートから始まり、ほかのシートも選べます。Excel で非表示の行を除くこともできます。Kitewell はファイルを読むだけで、変更しません。
- **共通の入力**：行が独自の値を持たない限り、すべての行が使う値です。空のセルには、使われる共通の値またはワークフローの既定値が灰色で表示されます。
- **ワークフローの実行結果から**：検索で見つかる物件のように、実行に項目を探させ、行を最新の状態に保ちます。[ワークフローの実行結果から行を作る](#ワークフローの実行結果から行を作る)を参照してください。

値は入力の型に従って読み取られます。文字列はそのまま、数値、`true` または `false`、リストやオブジェクトは JSON として扱います。ワークフローの変更後に整数の入力へ文字列が残っている場合など、型に合わない値は削除されず、理由とともに赤枠で示されます。シートは引き続き保存され、その行だけが値を直すまで実行されません。

ブックのセルは Excel での表示どおりに読み取られます。日付は `2026-10-01`、時刻は `09:30:00`、数値は桁区切りや通貨記号なし、パーセントは小数（12% は `0.12`）、TRUE と FALSE は `true` と `false`、`00123` のようなコードは先頭の 0 も含めて読み取ります。複数の行にまたがって結合したセルは各行に繰り返され、数式は Excel が最後に保存した結果になり、`#N/A` などの Excel のエラーを表示しているセルは空として読み取られ、その数が表示されます。古い `.xls` ファイルとパスワードで保護されたブックは読み取れません。先に `.xlsx` として保存するか、パスワードを解除してください。ファイルは 16 MiB までです。

シートは編集するそばから保存されます。

## ワークフローの実行結果から行を作る

ワークフローの実行で見つかったリストから行を作れます。新しい項目は、誰かが追加しなくても行になります。**取り込む**の中、または新しいシートの空の行の下で、**ワークフローの実行結果から行を作成**を選びます。

1. **ワークフロー**（シート自身のワークフローでもかまいません）と、その実行が出力する**リスト**を選びます。[Web サイト](/ja/docs/browser/)や[デスクトップ](/ja/docs/desktop/)のステップの**項目のリスト**、メールを探すステップが見つけたメール、JSON として読み取る出力が対象です。
2. 最新の実行で見つかった先頭の項目を確認します。まだ実行していない場合や、項目のフィールドが実行しないとわからない場合は、**今すぐ実行**を選びます。
3. **各入力項目を埋める値**では、各入力に同じ名前の項目のフィールドが割り当てられ、行は URL や ID で照合され、タイトルがラベルになります。どれも変更でき、リストを取得する実行の入力も設定できます。
4. **行を作成**を選びます。ワークフローが一度実行され、見つかった項目ごとに行が追加されます。

以降はツールバーに行の取得元が表示され、**行を更新**でワークフローをもう一度実行します。実行が成功すると次のようになります。

- 項目は、URL など同じキーを持つ行を更新します。同じキーで手で追加した行は、重複させずにそのまま引き継ぎます。
- 新しい項目は行として追加され、実行するまで**新規**と表示されます。
- 項目が消えた行は残り、**リストから消えた行**として灰色で表示されます。項目が戻れば、リストに戻った行として元に戻ります。すべての行、失敗した行、変更された行を実行するときは対象外で、選択すれば実行できます。**リストから消えた行**フィルターでこれらの行を表示し、まとめて削除できます。
- 各行には、いつからリストにあるか、またはいつからリストにないかが、行の詳細と**リストから消えた行**の印に表示されます。
- キーのない項目や、ほかの項目とキーが重複する項目はスキップされ、その数が表示されます。

バナーに変化の内容が表示され、**新しい行を表示**と**リストから消えた行を表示**で確認できます。どの項目にも値がなかった入力項目も示されます。実行が失敗した場合は何も変わらず、理由が表示されます。項目がまったくないリストや、キーを持つ項目がないリストでも何も変わりません。壊れた実行でシート全体が灰色になることはなく、本当に空になったリストでは、項目が戻るまで行がそのまま残ります。リストから埋めた入力には小さな印が付き、更新中に行った編集も保持されます。

取得元が合わなくなると、シートに理由が表示され、バッチの一覧にも印が付きます。ワークフローが削除された、リストを出力しなくなった、埋めている入力項目の名前が変わった、リストの項目からフィールドがなくなった、といった場合です。**取得元を変更**を選ぶと、対応付けを直した状態でパネルが開きます。ワークフローにない入力項目は外され、名前が変わった入力項目にはフィールドが割り当て直されます。保存すると行の値も移されるため、行は項目と照合され続け、重複して追加されることはありません。前回の更新が失敗したシートにも、バッチの一覧で印が付きます。

## 行を実行する

実行ボタンは、まだ実行していない行、または選択した行を開始します。**その他の実行方法**から、失敗した行の再実行、前回の実行から変更された行、すべての行を選べます。

開始する前に、すべての行がワークフローのパラメーターに照らして確認されます。必須の入力が欠けている行や、ワークフローが受け付けない値を持つ行があると何も開始されず、その行に理由が表示されます。

その後、各行はワークフローのキューで個別の実行になります。バナーには、完了した行数、同時に実行される数、ワークフローが共有キューを使う場合はそのキュー名、何行か完了した後はおおよその残り時間が表示されます。**default** キューはプロジェクト全体で同時に 5 件まで実行します。サイトが集中したリクエストを拒む場合は、バナーの**同時に実行する数を変更**から、そのキューを**キュー**ページで開けます。

- **待機中の行をキャンセル**は、まだ待っている行をキャンセルします。実行中の行は続きます。
- **すべて停止**は、実行中の行も停止します。

実行を開始すると、その時点のワークフローと各行の値の写しが保存されます。後からシートやワークフローを編集しても、キューに入った実行は変わりません。前回の実行から入力が変わった行には**変わっています**と表示され、**前回の実行から変更あり**フィルターで一覧できます。**実行とログ**から行の実行を再試行したり、ステップの状態を変更したりすると、その行にも反映されます。

失敗した行の前回の実行を選ぶと、止まったステップとそのエラーが表示されます。**（ステップ名）の再試行を設定**を選ぶと、ワークフローエディターでそのステップが開き、再試行の回数、間隔、バックオフをすぐに設定できます。集中したリクエストを拒むサイトも、時間をおいた再試行なら通ることがほとんどです。新しい再試行ルールは、行を再実行したときから適用されます。

## 結果を集める

結果列は、各実行から値を 1 つ集めます。値の取り方は 2 通りあり、列を追加するときに**値の取得元**で選びます。

### ワークフローが公開する値を写す

[Web サイトのステップ](/ja/docs/browser/)が抽出した価格のように、ステップがすでに値を集めている場合、列は各実行からその値をそのまま写します。モデルを使わず、費用もかからず、ステップが見つけたとおりの値が実行の完了と同時に入ります。列を作る前に実行した行も埋まります。

- ワークフローが値を公開している新しいシートでは、**このワークフローは次の値を公開しています。列として追加しますか?**の下に、それらがチェック済みで並びます。不要なもののチェックを外し、残りを追加します。
- **結果列**は、まだどの列も写していない公開値から始まり、その名前と型が付き、最新の実行で公開された値が横に表示されます。
- 数値の列に `¥12,800` が入った場合のように、列の型に合わない値は公開されたまま印付きで表示されます。その詳細から**列を文字列に変更**または**モデルに読み取らせる**を選べます。
- ワークフローが公開しなくなった値を写す列は、見出しに印が付きます。

写せるのは、実行の出力に届く値だけです。Web サイトやデスクトップの抽出、メールのステップ、コマンドのステップが宣言した結果が対象で、人が入力するフォームの回答やループ内のステップの値は含まれません。2 つのステップが同じ名前を公開した場合は、後に実行された方の値になります。

### モデルに実行を読み取らせる

それ以外の値は、**モデルが実行を読み取る**を選び、名前を付け、型（**文字列**、**数値**、**はい / いいえ**、**選択**、**段階**）を選び、単位や値が複数あるときにどれを取るかなど、読み取る内容を説明します。名前が公開値と一致するモデルの列には、代わりにその値を写す提案が表示されます。

これらの列は、**エージェントとモデル**の API モデルが埋めます。**モデルを選ぶ**で次を設定します。

- **抽出モデル**は、文字列と数値の列を読み取ります。判断モデルがない場合は、それ以外の列も読み取ります。各値には実行からの引用が付き、引用が一字一句そのままでは見つからなかった場合はその旨が示されます。
- **判断モデル**は任意です。はい / いいえ、選択、段階の列を確率付きで判断します。引用はありませんが、より速く低コストです。**この確信度未満は「要確認」にする**で、確認が必要な判断の基準を決めます。

値は、各実行が成功した後に読み取られます。モデルには実行の出力、ログ、テキストファイルが送られるため、それらを任せられるプロバイダーを選んでください。**N 行を埋める**は、値が欠けている完了済みの行を読み取り、行の詳細にある**もう一度読み取る**は、1 つの実行を読み直します。どちらもワークフローを再実行しません。列を変更する前に読み取った値は、古い値として示されます。

## スケジュールで実行し、変化を見る

毎朝の価格や物件の確認のように値の変化を追うには、シートのツールバーで**スケジュール**を選び、すべての行を再実行するタイミングを決めます。**毎時**、**毎日**、**平日**、**毎週**の指定時刻、または cron 形式の**カスタムスケジュール**から選べます。シートの実行は 1 時間に 1 回までです。次回の実行は、ツールバーとシートの一覧に表示されます。

- **スケジュールはこのデバイスに属します。** シートとともに同期されないため、チームメイトが共有したシートは、誰かがスケジュールを設定したデバイスでだけ実行され、うっかり 2 台で実行されることはありません。
- **このコンピューターが起動している間に実行されます。** オフやスリープ中に逃した実行について、復帰時にどうするかを選べます。次の実行の方が近くない限り実行する（既定）、必ず実行する、5 分以内に復帰しなければスキップする、の 3 つです。いずれの場合も、逃した実行は最大 1 回だけ行われます。
- 前回の実行がまだ続いている時刻はスキップされます。開始できなかった実行は、理由とともにスケジュールに印が付きます。
- ワークフローの実行結果から行を作るシートは、先に行を更新します。新しい項目は新しい行として実行され、リストから消えた行は対象外になります。リストの取得にかかる時間だけ待ってから実行します。行をそのまま実行するには、**先に … から行を更新する**のチェックを外します。

各行は、同じ入力での前回の実行で読み取った値を保持します。それ以降に変わった結果はセルに印が付きます。数値が上がった・下がった場合は矢印、それ以外は点で示され、変更前の値はマウスを重ねたときとセルの詳細に表示されます。バナーに変化の数が表示され、**表示する**で**結果が変わった行**フィルターが適用されます。空白や大文字・小文字だけの違いは変化とみなしませんが、モデルは同じ値を実行ごとに違う言い回しで返すことがあるため、できるだけステップが公開する値を写してください。

## シートのアクティビティと値の履歴を見る

シートのツールバーの**アクティビティ**には、過去 1 年間に完了した実行が新しい順に表示されます。各実行について、実行した行数と失敗した行数、列ごとに上がった・下がった・変わった値の数、新しい行・リストに戻った行・リストから消えた行、変わった値とその変更前の値がわかります。変わった値を選ぶと、その行が開きます。実行は、すべての値を読み取ったあとに表示されます。

値を選ぶと、その 1 年間の推移が表示されます。数値は線でも示されます。

この履歴はシートを実行したデバイスに残ります。1 か月ごとに 1 つのファイルにまとめられ、月が終わると圧縮され、1 年を過ぎると削除されます。

## 書き出し、複製、削除

- **Excel に書き出す**と**CSV を書き出す**は、入力、値、各判断の確率、変わった結果の変更前の値、各行の実行を、シート名と日付を付けたファイルに保存します。ブックは見出しが固定されフィルター付きで開き、数値と日付は Excel で並べ替えられるセルになり、各行の状態は色分けされます。もう一度取り込むと、入力は自動で割り当てられます。ワークフローの実行結果から行を作るシートでは、**リスト内の状態**の列に、新しい行かリストから消えた行かが入ります。
- シートのメニュー（**シートの操作**、⋯）には、同じ行、入力、結果列、モデルを持つ写しを作る**複製**と、同じ設定で空の行を 1 つだけ持つ**行なしで複製**があります。値はそれを生んだ実行に属するため、写しは結果のない状態で始まります。
- **シートを削除**は、シートと、このデバイスで読み取った値を削除します。実行は**実行とログ**に残ります。バッチの実行中は、そのシートを削除できません。

## アラート、アシスタント、MCP

- Kitewell Pro では、**バッチを完了したとき**の[アラート](/ja/docs/alerts/)で、実行のすべての行が終わって値を読み取った後に、成功しなかった行の数と、「価格：9 件下落、3 件上昇」のような列ごとの変化、先に行を更新した場合は新しい行、リストに戻った行、リストから消えた行の数が知らされます。すべての行が成功して何も変わらなかったスケジュール実行は通知せず、開始できなかったスケジュール実行は理由とともに通知します。バッチの行は、人の対応を待つ場合を除き、1 行ずつ実行のアラートを出しません。
- アシスタントは、行や列の追加・変更を提案できます。提案は、適用する、適用して対象の行を実行する、または却下するまで、開いているシートに表示されます。適用した変更は元に戻せます。
- [MCP クライアント](/ja/docs/mcp/)は、シートの一覧表示と読み取り（ワークフローが公開する値や、変わった値の変更前の値を含む）、作成・置き換え・削除、公開値を写す列の設定、ワークフローの実行結果から行を作る設定とその更新、このデバイスでのスケジュール設定、行の実行、値の読み取り、実行のキャンセルができます。シートの報告には、最近完了した実行とその変化も含まれます。

## このデバイスに残るもの

シート自体はプロジェクトに属するため、プロジェクトの書き出しに含まれ、[Dagu Cloud と同期](/ja/docs/cloud-sync/)されます。行の取得元と、リストから消えた行もシートとともに同期されます。行の状態、実行から読み取った値とその変更前の値、最新の行の更新、1 年分のアクティビティと値の履歴、シートのスケジュールは、実行したデバイスに残ります。
