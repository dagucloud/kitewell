---
title: シークレット
---

API トークンなどの 1 行の認証情報は、値をワークフロー定義に直接書かず、プロジェクトのシークレットを使ってください。

## 認証情報を追加する

1. **シークレット** を開き、**シークレットを作成** を選びます。
2. `services/api-token` のような参照と、その値を入力します。
3. ワークフローエディターで、そのシークレットが必要なフィールドに対してシークレットを選ぶか、**DAG で使う** を使って参照の構文を取得します。

保存した値を Kitewell から読み出すことはできません。**値を置き換える** を使うと、参照を変えずに認証情報をローテーションできます。シークレットを無効化または削除すると、以降そのシークレットは解決されなくなります。

シークレットの名前と説明はプロジェクトに属し、値は設定したデバイスにとどまります。**値が必要** は、プロジェクトが使うシークレットのうち、このデバイスにまだ値がないものです。**値を設定** を選んでください。**このデバイスのみ** は、プロジェクトにまだ含まれていないシークレットです。**宣言** を選ぶとプロジェクトに追加されます。

## インポートした API でシークレットを再利用する

**API ライブラリ** で接続を開き、認証タイプを選んで、そのプロジェクトにある既存の **シークレットの参照** を選択または入力します。その接続を使うすべてのワークフローアクションが、自動的に認証情報を受け取ります。同じ参照のまま認証情報をローテーションするには、**シークレット** の **値を置き換える** を使います。接続やワークフローを編集する必要はありません。対応するタイプについては [API のインポート](/ja/docs/apis/#connect-credentials)を参照してください。

## 境界を理解する

シークレットは Dagu によってディスク上で暗号化されます。タスクは実行時に認証情報を受け取ります。ワークフローを編集・実行できるクライアントは、それらの認証情報にアクセスするコマンドを書けます。プロジェクトの分離は、オペレーティングシステムのサンドボックスではありません。

実行ログでは、シークレットの値そのものはマスクされますが、エンコードや変換をした値はマスクされない場合があります。認証情報を出力しないでください。複数行の値には対応していません。

## エクスポート、同期、バックアップ

プロジェクトのエクスポートには、インポートした API 接続内のものも含めてシークレットの名前、説明、参照が保持されますが、管理されたシークレットの値は含まれません。受け取る側のプロジェクトでは各シークレットが **値が必要** と表示されます。ワークフローを実行する前に値を設定してください。

[Dagu Cloud とのプロジェクトの同期](/ja/docs/cloud-sync/)も同じです。シークレットの名前と説明はプロジェクトと一緒に同期され、シークレットの値が Dagu Cloud に送信されることはありません。プロジェクトを同期する各デバイスが、値をそれぞれ設定します。

ワークスペースのバックアップにも、管理されたシークレットとその復号鍵は含まれません。復元後に、必要な認証情報を再入力してください。復旧に必要な認証情報は、別途安全な場所に記録しておいてください。

どちらのアーカイブも暗号化されていません。ワークフロー、OpenAPI 仕様、ソース URL に直接書き込んだ認証情報はアーカイブに残ります。バックアップには、機密性の高いデバイス設定が含まれることもあります。共有する前にアーカイブを確認し、共有ストレージに移す前に独自に暗号化してください。
