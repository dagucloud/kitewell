---
title: AI エージェントとモデル
---

Kitewell は、ローカルにインストールされた AI コマンドラインツールと、API ベースのモデルを使えます。AI クレジットの提供や、それらのツールへの代理サインインは行いません。設定は **エージェントとモデル** で行います。

## コマンドラインエージェント

使いたいコマンドラインエージェント（Claude Code、Codex、Cursor、Gemini、GitHub Copilot、OpenCode、Aider、Amp、Cline、DeepSeek、Droid、Goose、Kiro、Pi、Qwen など）をインストールしてサインインします。その他のツールは **カスタムコマンド** で実行できます。このデバイスにインストール済みで、まだどのエージェントも使っていないツールは **このデバイスで検出** に表示されます。

**CLI エージェントを追加** を選び、ハーネスとモデルを選んで、**エージェントをテスト** でツールがインストールされサインイン済みであることを確認します。ワークフローに **AI エージェントに依頼** タスクを追加し、エージェントを選んで、プロンプトとコンテキストを入力します。作業フォルダーと権限を確認してください。エージェントは、そのプロセスから利用できるファイルやツールを操作できます。

## API モデル

**API モデルを追加** を選び、プロバイダーを選びます。Anthropic、OpenAI、Google Gemini、OpenRouter、Z.ai、OpenCode Zen、または Ollama や vLLM などのローカルサーバーを使えます。プロバイダーの API キーはプロジェクトの[シークレット](/ja/docs/secrets/)に保存し、そのシークレットをモデルの認証情報として選びます。ローカルサーバーにはキーが不要で、通常のローカルアドレスで動いている場合は **ベース URL（任意）** を空のままにできます。OpenRouter、OpenCode Zen、動作中のローカルサーバーでは、**モデル ID** にプロバイダーが提供するすべてのモデルが一覧表示され、名前の一部を入力して検索できます。**モデルをテスト** は短いリクエストを送信して設定を確認します。

API モデルは、**モデルに尋ねる** タスク、アシスタント、失敗の診断、[バッチシート](/ja/docs/batches/)の結果列、**Web サイトを自動操作** タスクで使われます。

**判断モデルを追加** では、OpenRouter または TypeSafe のモデルを設定します。**AI に判断を依頼** タスクは、このモデルで分類、スコア付け、はい／いいえで答える質問への回答を行い、後続のステップが分岐に使える構造化された回答を返します。バッチシートでは、はい / いいえ、選択、段階の列を確率付きで判断するのにも使えます。

## アシスタント

アシスタントは、ワークフローの作成や修正を手伝います。どのプロジェクトページでも **アシスタント** から開くか、⌘J（Ctrl+J）を押します。編集権限を持つユーザーが使え、プロジェクトの API モデルを 1 つ使います。モデルがない場合は、管理者がパネルから接続できます。API キーはプロジェクトのシークレットとして保存されます。

- **ワークフロー**：新規または変更したワークフローを、変更内容とグラフのプレビュー付きのカードで提案します。**適用** を選ぶまで何も保存されません。**エディターで編集** や **却下** も選べます。新しいスケジュール付きのワークフローは、**スケジュールをオンにする** にチェックしない限り一時停止の状態で保存されます。適用後は **今すぐ実行** で実行フォームが開き、更新は元に戻せます。アシスタント自身がワークフローを実行したり削除したりすることはありません。
- **シート**：[バッチシート](/ja/docs/batches/)の行や列を提案します。提案は、適用するか却下するまで、開いているシートに表示されます。
- **質問とページ**：短い質問フォームで尋ねたり、指定した公開 Web ページを読んだりできます。このデバイスやそのネットワーク上のアドレスは読みません。
- **シークレット**：シークレットを名前で依頼できます。値はカードに入力し、プロジェクトのシークレットストアに保存されます。アシスタントが値を見ることはありません。管理者のアシスタントはシークレット名を一覧できますが、値は見られません。

失敗した実行で **アシスタントに聞く** を選ぶと、原因の調査と修正案を依頼できます。会話はこのデバイスに残り、プロジェクトごとに保持する数は **デバイス設定 → アシスタント** で設定します。

<a id="failure-diagnosis"></a>

## 失敗の診断

Kitewell は、実行が失敗した理由を説明できます。**プロジェクト設定 → 失敗の診断** で **失敗した実行を自動で診断** をオンにし、使う API モデルを選び、ワークフローごとにプロジェクトの設定に従うか、オンかオフかを決めます。

診断されるのは、失敗が続き始めた最初の失敗だけで、失敗した実行のたびではありません。失敗した実行に表示される結果は、**もう一度試す**、**対応が必要**、**ワークフローの変更**、**不明** のいずれかで、原因と次の一手が添えられます。どの失敗した実行でも **診断** を選べ、**もう一度診断** で新しい答えを得られます。モデルには、失敗したステップの結果、ログの抜粋、ワークフローの定義が送られ、モデルがツールを実行することはありません。診断はこのデバイスに残り、実行とともに削除されます。

## 実行を確認する

実行する前に、**ツール → AI プロンプトを確認** で作成したプロンプトを確認できます。実行後は **実行とログ** を開き、記録されたプロンプトとタスクの出力を確認します。

AI のプロンプトとコンテキストは、選択したプロバイダーまたはツールに送信されます。アシスタント、診断、バッチシートが読み取るログ、成果物、実行の出力も含まれます。プロバイダーの課金、データ保持、プライバシーのルールが適用されます。Kitewell のワークスペースがローカルにあっても、すべてのタスクがオフラインで完結するわけではありません。
