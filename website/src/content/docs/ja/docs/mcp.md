---
title: MCP と API アクセス
---

MCP を使うと、対応する AI クライアントから Kitewell のワークフローを操作できます。スクリプトやその他の連携には REST アクセスを使えます。

## ローカルクライアントを接続する

1. **このデバイス → MCP** を開きます。
2. **AI エージェントを接続** を選び、クライアントに名前を付けて、権限（**読み取り専用**、**ジョブの実行**、**編集と実行**）、アクセスできるプロジェクト、任意の有効期限を選びます。
3. Kitewell に表示されるエンドポイントと接続情報を使います。ローカル MCP エンドポイントの既定値は `http://127.0.0.1:19742/mcp` です。
4. キーを Bearer 認証情報として送信するようにクライアントを設定します。クライアントがカスタムの Bearer 認証情報に対応している必要があります。OAuth によるサインインには対応していません。

各キーがアクセスできるのは、許可したプロジェクトだけです。選択したプロジェクト、または現在と今後のすべてのプロジェクトを許可できます。選択したプロジェクトに限定したキーは、後から作成されたプロジェクトにはアクセスできません。まずクライアントにプロジェクトの一覧を取得させ、プロジェクト固有の MCP 呼び出しや REST リクエストでは、選択した `projectId` を渡してください。1 つのプロジェクトだけにアクセスできるキーでは ID を省略できますが、複数のプロジェクトにアクセスできるキーでは 1 つを指定する必要があります。

無料プランで発行できる API キーは 1 つです。Kitewell Pro では何個でも発行できます。Pro の契約が切れても、それまでに発行したキーは引き続き使えます。キーを取り消すと、その分だけ新しいキーを発行できます。

## インポートした API を使う

編集権限を持つ MCP クライアントは、OpenAPI 仕様書をインポートして API 接続を保存し、そのオペレーションからワークフローを作成できます。クライアントは、インポートしたリクエストとレスポンスのスキーマを調べて入力を選び、結果を後続のステップで使えます。ワークフローを実行するには実行権限または編集権限が必要で、その実行は実行履歴に表示されます。

MCP サーバーは `read`、`change`、`execute` の 3 つのツールを公開しています。`target: "reference"` を指定して `read` を呼び出し、使い方のガイドを取得してから、次の流れで進めます。

1. `change` に `type: "preview_api"` と、`spec`（JSON または YAML のテキスト）か `url` のどちらかを指定してプレビューします。プレビューでは、接続は保存されず、API オペレーションも実行されません。
2. `change` に `type: "upsert_api"`、`id`、`api` 定義を指定して保存します。`api.spec` を指定するか、省略して `api.sourceUrl` から 1 回だけ取得させます。`api.auth.type` には `none`、`bearer`、`apiKey`、`basic` のいずれかを設定します。認証を使う場合は、`api.auth.secretRef` で既存のプロジェクトシークレットを指定します。シークレットの値の作成やローテーションは、ローカルの GUI で行います。
3. `read` で検出します。`target: "apis"` は接続を一覧表示します。`target: "api_operations"` は `id` と任意の `query` で API を検索します。`target: "api_operation"` に `id` と `operationId` を指定すると、その入力、レスポンス、出発点となるワークフローステップが返されます。
4. ワークフローに `api.request` ステップを追加し、通常のワークフローツールで検証、保存、実行します。返されるステップはテンプレートです。実行する前に例を確認し、プレースホルダーを置き換えてください。

`upsert_api` で更新すると、接続全体が置き換えられます。先に `id` を指定して `target: "api"` を読み取り、残したいフィールドを保持してください。`change` に `type: "delete_api"` と `id` を指定すると接続を削除できますが、保存済みのワークフローがその接続を使っていない場合に限られます。サポートされる仕様書、認証、エクスポート、更新時の動作については [API のインポート](/ja/docs/apis/)を参照してください。

API のインポートと接続の管理は、GUI と MCP で行えます。公開 REST API は、保存済みの API 接続を使うワークフローの実行を含むワークフロー操作を提供しますが、API カタログの管理やシークレットの管理は提供しません。

## 権限

タスクに必要な最小限のアクセス権から始めてください。読み取り権限では、ワークフローと履歴を確認できます。実行権限では、処理を開始できます。編集権限では、Kitewell を実行しているユーザーとして動作するコマンドを含め、ワークフローの定義を変更できます。不要になったキーは Kitewell で取り消してください。

## リモートクライアント

リスナーは既定でループバックアドレスで待ち受けます。リモートクライアントには、到達可能な HTTPS エンドポイントと、ご自身で運用する安全なネットワーク構成が必要です。管理用インターフェースは localhost に限定してください。保護されていない HTTP リスナーをインターネットに公開しないでください。

クライアントの認証情報は安全に保管し、スクリーンショットや問題の報告から取り除いてください。クライアントの認証方法がはっきりしない場合は、[サポートにお問い合わせください](/ja/support/)。
