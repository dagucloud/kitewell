---
title: MCP と API アクセス
---

MCP を使うと、対応する AI クライアントから Kitewell のワークフローを操作できます。スクリプトやその他の連携には REST アクセスを使えます。

## ローカルクライアントを接続する

1. **このデバイス → MCP** を開きます。
2. **AI エージェントを接続** を選び、クライアントに名前を付けて、権限（**読み取り専用**、**ワークフローの実行**、**編集と実行**）、アクセスできるプロジェクト、任意の有効期限を選びます。
3. Kitewell に表示されるエンドポイントと接続情報を使います。ローカル MCP エンドポイントの既定値は `http://127.0.0.1:19742/mcp` です。
4. キーを Bearer 認証情報として送信するようにクライアントを設定します。クライアントがカスタムの Bearer 認証情報に対応している必要があります。OAuth によるサインインは [ChatGPT と Claude](#connect-chatgpt-or-claude) だけのものです。

各キーがアクセスできるのは、許可したプロジェクトだけです。選択したプロジェクト、または現在と今後のすべてのプロジェクトを許可できます。選択したプロジェクトに限定したキーは、後から作成されたプロジェクトにはアクセスできません。まずクライアントにプロジェクトの一覧を取得させ、プロジェクト固有の MCP 呼び出しや REST リクエストでは、選択した `projectId` を渡してください。1 つのプロジェクトだけにアクセスできるキーでは ID を省略できますが、複数のプロジェクトにアクセスできるキーでは 1 つを指定する必要があります。

無料プランで使える API キーと接続済みのアプリは、合わせて 1 つです。Kitewell Personal と Team では何個でも使えます。どれかを取り消すと、その分だけ新しく追加できます。有料プランが終わると、その 7 日後に、無料プランを超える分のキーとアプリが使えなくなります。どれを残すかは選べます。[プランが終わったとき](/ja/docs/cloud-sync/#プランが終わったとき)を参照してください。

## ChatGPT や Claude を接続する

Web、デスクトップ、モバイルの ChatGPT と Claude は、`https://mcp.kitewell.app/mcp` を通じてお使いのコンピューターの Kitewell に接続します。コンピューターは、キーの場合と同じく、すべての呼び出しをアプリの権限とプロジェクトに照らして確認します。Dagu Cloud のアカウントが必要で、そのコンピューターの Kitewell が Dagu Cloud に[サインイン](/ja/docs/cloud-sync/#サインイン)している必要があります。

1. Kitewell で **このデバイス → MCP** を開き、**ChatGPT を接続** または **Claude を接続** を選びます。
2. アプリに許可すること、つまり権限（**読み取り専用**、**ワークフローの実行**、**編集と実行**）とプロジェクトを選び、**保存して手順を表示** を選びます。リモートアクセスがオンになり、貼り付ける URL とそのアプリでの手順が表示されます。選んだ内容は、次に同じアプリを接続するときのために保存されます。
3. 下の手順で、その URL をカスタムコネクタとしてアプリに追加します。
4. アプリが Dagu Cloud（console.dagu.sh）を開きます。Kitewell がサインインしているアカウントでサインインします。
5. 同意のページは、選んだ内容が入力された状態で開きます。コンピューター、権限、プロジェクトを確認し、必要なら変更してから許可します。

その後、アプリは **このデバイス → MCP** の **接続済みのアプリ** に、権限、プロジェクト、最終使用とともに表示されます。ここで権限を変更したり、アプリを失効させたりできます。変更はアプリの次の呼び出しから適用されます。**リモートアクセス** をオフにすると接続を閉じます。接続済みのアプリは一覧に残り、オンに戻すと再び使えます。

### Claude

1. **カスタマイズ → コネクタ** を開き、**+ 追加** を選んでから **カスタムコネクタを追加** を選びます。
2. 名前を Kitewell とし、URL を貼り付けて **続行** を選びます。提案されたサインインの設定はそのままにして **追加** を選びます。
3. サインインし、権限とプロジェクトを確認して、アクセスを許可します。

Team プランと Enterprise プランでは、先にオーナーが **組織設定 → コネクタ** でコネクタを追加し、その後メンバーがそれぞれ **接続** を選びます。Claude の Free プランで使えるカスタムコネクタは 1 つです。

### ChatGPT

ChatGPT は Web 版からだけ、開発者モードで接続できます。

- Plus と Pro では、ChatGPT が使えるのは `read` や `show` など Kitewell の読み取り専用のツールだけです。実行の開始やワークフローの編集には、ChatGPT Business、Enterprise、Edu が必要です。
- Business では、開発者モードを使えるのは管理者とオーナーだけです。Enterprise と Edu では、まず管理者が許可します。

プラグインに Kitewell のアイコンを付けるには、先に <a href="/kitewell-icon-256.png" download>Kitewell のアイコン（PNG）をダウンロード</a>してください。256 × 256 px で、ChatGPT の上限の 10 KB に収まります。

1. **プラグイン** を開き、**追加** を選んでから **カスタム MCP サーバーを作成** を選びます。見つからない場合は、先に **設定 → セキュリティとログイン**（Business、Enterprise、Edu では **設定 → アプリ → 詳細設定**）で **開発者モード** をオンにします。
2. 名前を Kitewell とし、必要なら Kitewell のアイコンを追加して、**サーバーURL** に URL を貼り付けます。**OAuth** はそのままにし、**理解したうえで続けます** にチェックを入れて、**プラグインとして作成** を選びます。
3. **Kitewell に進む** を選び、Dagu Cloud にサインインして、権限とプロジェクトを確認し、**許可** を選びます。
4. **チャットで試す** を選びます。どのチャットでも、**@** を入力して Kitewell を選ぶか、**+** のツールメニューから選ぶこともできます。

Kitewell は **プラグイン → 個人用 → 自分で作成** に表示され、そのページには接続したアカウントが表示されます。

### コンピューターに必要なこと

コンピューターの電源が入り、スリープしておらず、Kitewell が動いている必要があります。そうでない場合も、アプリには Kitewell のツールが表示されますが、どの呼び出しにも、そのコンピューターの Kitewell に接続できないという答えが返ります。そのコンピューターで Kitewell を開いてから、もう一度試してください。それでも失敗する場合は、[トラブルシューティング](/ja/docs/troubleshooting/#chatgpt-and-claude)を参照してください。

## MCP Events

ChatGPT はイベントを購読し、イベントが起きたときに署名付きの Webhook を受け取れます。

- `run.finished`：実行が終了した。1 つの `runId` や、知らせるステータスを指定できます。
- `run.needs_input`：実行が承認、人のタスク、質問で待っている。
- `batch.finished`：シートの行の[バッチ](/ja/docs/batches/)が終了した。
- `schedule.missed`：スケジュールの実行を逃した。

購読は **接続済みのアプリ** のアプリの下に直近の配信とともに表示され、**削除** で取り除けます。イベントを見つけて送るのはお使いのコンピューターの Kitewell なので、届くのは Kitewell が動いている間だけです。MCP Events は、[アラート](/ja/docs/alerts/)と同じく Kitewell Personal と Team の機能です。

## クライアントにできること

Kitewell には `read`、`show`、`preview_api`、`change`、`execute` の 5 つのツールがあります。どのツールも、読み取るだけか、書き込むだけのどちらかです。キーや接続済みのアプリによる接続には、その権限で使えるツールだけが表示されるため、読み取り専用の接続に書き込むツールが見えることはありません。

| 権限 | 表示されるツール |
| --- | --- |
| **読み取り専用** | `read`、`show` |
| **ワークフローの実行** | `read`、`show`、`execute` |
| **編集と実行** | `read`、`show`、`preview_api`、`change`、`execute` |

権限で許可されていない呼び出し（以前の権限のときのツール一覧をクライアントが使い続けた場合など）は拒否され、Kitewell のどこで権限を変更できるかが示されます。

- **`read`**：プロジェクト、ワークフローとそのスキーマ、ログや成果物を含む実行、エージェントと API モデル、サーバー、キュー、ワークフローの既定値、インポートした API、[バッチシート](/ja/docs/batches/)とその値、プロジェクトの[ナレッジ](/ja/docs/knowledge/)を読み取ります。失敗した実行には、[失敗の診断](/ja/docs/ai/#failure-diagnosis)があればそれも含まれます。再実行で再利用できるステップのプレビュー（**ワークフローの実行**）と、ワークフローの YAML を保存せずに行う確認（**編集と実行**）も読み取りです。何も変更せず、コンピューターの外にもアクセスしません。`target: "reference"` を指定して呼び出すと、使い方のガイドを取得できます。
- **`show`**：ワークフローの依存関係のグラフを描き、実行を指定すると各ステップの状態も示します。ChatGPT と Claude では、進行中の実行を追いかけるインタラクティブな表示になります。ほかのクライアントには、ステップが順に、それぞれの状態とともにテキストで返ります。読み取るだけです。
- **`preview_api`**：渡された OpenAPI ドキュメントを読むか、URL から取得して、そのオペレーションを一覧にします。何も保存しません。読み取るだけですが、URL から取得するときはコンピューターの外にアクセスします。
- **`change`**：ワークフロー、エージェントとモデル、サーバーとサーバーグループ、キュー、ワークフローの既定値、API 接続、シート（このデバイスでのシートのスケジュールを含む）、ナレッジのページを作成、置き換え、削除します。既存のものを上書きしたり削除したりでき、API のインポートではソース URL から取得し、有効なスケジュールを保存するとワークフローが実行されることがあります。
- **`execute`**：実行の開始、再試行、再実行、キャンセル、人の対応を待つステップの承認、却下、差し戻し、完了、入力を待つ Web サイトやデスクトップのステップへの回答や再開、シートの行の実行、値の読み取り、キャンセルを行います。**編集と実行** では、シートの行をソースから更新することや、シートを Excel のブックにリンクすることもできます。ワークフローのコマンドはファイルを変更したり、ほかのサービスにアクセスしたりできます。キャンセルしても、すでに実行された処理は元に戻りません。

ポーリングせずに実行を見届けるには、開始、再試行、再実行のときの `execute`、または `target: "run"` を指定した `read` に、最大 60 秒の `wait` を渡します。実行が終わるか、人の対応を待つステップで止まると、すぐに答えが返ります。先に時間切れになった場合はその時点の実行が返るので、もう一度 `wait` を付けて読み取ると、続けて見届けられます。[MCP Events](#mcp-events) に対応したクライアントは、代わりに `run.finished` を購読できます。

既存の定義を置き換えたり削除したりするには、直前の読み取りで返された `version` が必要です。これにより、クライアントが確認していない変更を上書きすることはありません。競合した場合は、もう一度読み取り、内容を確認してから意図して送り直してください。

## インポートした API を使う

編集権限を持つ MCP クライアントは、OpenAPI 仕様書をインポートして API 接続を保存し、そのオペレーションからワークフローを作成できます。クライアントは、インポートしたリクエストとレスポンスのスキーマを調べて入力を選び、結果を後続のステップで使えます。ワークフローを実行するには実行権限または編集権限が必要で、その実行は実行履歴に表示されます。

次の流れで進めます。

1. `preview_api` ツールに、`spec`（JSON または YAML のテキスト）か `url` のどちらかを指定してプレビューします。プレビューでは、接続は保存されず、API オペレーションも実行されません。
2. `change` に `type: "upsert_api"`、`id`、`api` 定義を指定して保存します。`api.spec` を指定するか、省略して `api.sourceUrl` から 1 回だけ取得させます。`api.auth.type` には `none`、`bearer`、`apiKey`、`basic` のいずれかを設定します。認証を使う場合は、`api.auth.secretRef` で既存のプロジェクトシークレットを指定します。シークレットの値の作成やローテーションは、ローカルの GUI で行います。
3. `read` で検出します。`target: "apis"` は接続を一覧表示します。`target: "api_operations"` は `id` と任意の `query` で API を検索します。`target: "api_operation"` に `id` と `operationId` を指定すると、その入力、レスポンス、出発点となるワークフローステップが返されます。
4. ワークフローに `api.request` ステップを追加し、通常のワークフローツールで検証、保存、実行します。返されるステップはテンプレートです。実行する前に例を確認し、プレースホルダーを置き換えてください。

`upsert_api` で更新すると、接続全体が置き換えられます。先に `id` を指定して `target: "api"` を読み取り、残したいフィールドを保持し、その `definitionVersion` を `version` として渡してください。`change` に `type: "delete_api"`、`id`、`version` を指定すると接続を削除できますが、保存済みのワークフローがその接続を使っていない場合に限られます。サポートされる仕様書、認証、エクスポート、更新時の動作については [API のインポート](/ja/docs/apis/)を参照してください。

API のインポートと接続の管理は、GUI と MCP で行えます。公開 REST API は、保存済みの API 接続を使うワークフローの実行を含むワークフロー操作と、バッチシート（シートの一覧、保存、スケジュール設定、削除、行の開始とキャンセル、値の読み取り）を提供します。API カタログの管理やシークレットの管理は提供しません。

## 権限

タスクに必要な最小限のアクセス権から始めてください。読み取り権限では、ワークフローと履歴を確認できます。実行権限では、処理を開始できます。編集権限では、Kitewell を実行しているユーザーとして動作するコマンドを含め、ワークフローの定義を変更できます。不要になったキーや接続済みのアプリは Kitewell で取り消してください。

## リモートクライアント

リスナーは既定でループバックアドレスで待ち受けます。ChatGPT と Claude は、上で説明したとおり Kitewell のリレーを通じて接続します。それ以外のリモートクライアントには、到達可能な HTTPS エンドポイントと、ご自身で運用する安全なネットワーク構成が必要です。管理用インターフェースは localhost に限定してください。保護されていない HTTP リスナーをインターネットに公開しないでください。

クライアントの認証情報は安全に保管し、スクリーンショットや問題の報告から取り除いてください。クライアントの認証方法がはっきりしない場合は、[サポートにお問い合わせください](/ja/support/)。
