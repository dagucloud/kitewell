---
title: Web サイトを自動操作
---

**Web サイトを自動操作** ステップは、自然な言葉で書いた指示に従って、コンピューター上の本物のブラウザーを操作します。ページを開く、クリックや入力をする、情報を集める、ページの表示を確かめる、ファイルをダウンロードする、サイトがコードを求めたときにあなたに尋ねる、といったことができます。クリックを記録したりセレクターを書いたりする代わりに、何をするかを説明すれば、各ページでの操作方法は API モデルが判断します。

スケジュール、[バッチシート](/ja/docs/batches/)、ワークフローのほかのステップと組み合わせれば、RPA（ロボティック・プロセス・オートメーション）ツールが担う作業をこなせます。

- 仕入れ先のポータルから今月の請求書をダウンロードして保存する。
- スプレッドシートにあるすべての注文の状況を調べ、結果を集める。
- Web のダッシュボードの数値を、日次レポートや別のシステムに写す。
- リストの行ごとに、同じ Web フォームに入力する。
- リリース後に、サイトのサインインや購入手続きが動くことを確かめる。

操作はあなたのコンピューターのあなたの Chrome で実行され、サインインもデバイスに残ります。

## 最初の実行の前に

- **Chrome**：macOS では Google Chrome を `/Applications` にインストールします。Windows では、インストール済みの Chrome または Microsoft Edge を使います。Chromium、Brave、macOS の Edge、または別の場所にある Chrome を使う場合は、**デバイス設定 → ブラウザー → ブラウザーの実行ファイル** を設定します。
- ステップまたは **デバイス設定** にある **ブラウザーを確認** は、実行時と同じように Kitewell のバックグラウンドサービスからブラウザーを一度開き、起動できないブラウザーをスケジュール実行の途中ではなく今のうちに見つけます。macOS では、macOS の確認も先に済ませ、まだ開くことを許可されていないブラウザーやエンジンも知らせます。
- **モデル**：ステップで[エージェントとモデル](/ja/docs/ai/)の API モデルを選ぶか、ワークフローの **設定** で **ブラウザーとデスクトップのステップの既定モデル** を設定します。Anthropic、OpenAI、Gemini のモデルを使ってください。小さなローカルモデルでは、通常ブラウザーを操作できません。

## 最初の Web サイトのステップを作る

この例では、ショップの Web サイトで注文を調べ、その状況を次のステップに渡します。

1. ジョブを作成し、タスクの選択肢から **Web サイトを自動操作** を追加します。後のステップが収集した値を読めるように、ステップに `order` などの ID を付けます。
2. **モデル** を選び、**開始ページ（任意）** に `https://shop.example.com/orders` など最初に開くページを設定します。
3. **ブラウザーが入力する値** に `order` を追加し、注文番号を設定します。直接入力した文字列、ワークフローの入力、シークレットのいずれかを使えます。
4. **ブラウザーでのステップ** に次を追加します。
   - **ページで操作する**：`Type %order% into the order search box and press Enter`
   - **次を確認する…**：`The order's details are shown`
   - **情報を集める**：何を探すかに `The order's status and expected delivery date` と書き、`status` と `delivery` を **文字列** として収集します。
5. **ブラウザーウィンドウを表示する** をオンにし、**テスト** を選んで、ステップ単体の動きを確認します。
6. `${steps.order.outputs.status}` を使う後続のステップを追加します。

指示は日本語でも書けます。同じワークフローを YAML で書くと次のとおりです。

```yaml
type: graph
steps:
  - id: order
    name: Look up an order
    action: browser.run
    with:
      url: https://shop.example.com/orders
      variables:
        order: "10042"
      do:
        - act: Type %order% into the order search box and press Enter
        - expect: The order's details are shown
        - extract:
            instruction: The order's status and expected delivery date
            schema:
              type: object
              properties:
                status:
                  type: string
                delivery:
                  type: string
  - id: report
    name: Report the status
    depends: [order]
    run: echo "${steps.order.outputs.status} (${steps.order.outputs.delivery})"
```

新しいワークフローの **または例から始める** には、**Web サイトからデータを集める** と **一度サインインしてから収集** があります。

## ブラウザーでできること

操作は 1 つのブラウザーで順に実行されます。1 つの操作には 1 つの動作を書きます。

- **ページを開く**：**Web アドレス** に移動します。
- **ページで操作する**：`最新の請求書の横にある「ダウンロード」をクリックする` のように、**何をするか（自然な言葉で）** を書きます。`%name%` は、ブラウザーが入力する値か、それまでの回答を入力します。
- **情報を集める**：**何を探すか** を書き、**収集する値** で各値の名前、型（**文字列**、**数値**、**はい / いいえ**、**リスト**）、モデル向けの説明を設定します。各値は、後続のステップが `${steps.<id>.outputs.<name>}` で読める結果になります。
- **次を確認する…**：**ページは次の状態であること…** を書きます。そうでなければステップは失敗します。**自然な言葉で（モデルが判断）** の確認はモデルが判断し、**ページに次のテキストがある**、**アドレスに次を含む**、**要素が表示される（CSS セレクター）** はモデルを使わずにページを読むため、毎回同じ答えになります。**確認を続ける時間（任意）** で、ページがその状態になるまで待てます。
- **待機**：**一定時間**、または **要素が表示されるまで（CSS セレクター）** 待ちます。
- **スクリーンショットを撮る**：PNG として実行の成果物に保存します。
- **私に入力を求める**：**あなたに表示する質問** を表示し、ワンタイムコードなどの回答があるまで一時停止します。**回答の名前** で、後の操作から使う名前を付けます。

**実行条件と制限時間** で、条件を満たすときだけ操作を実行したり、所要時間を制限したりできます。ダウンロードしたファイルは実行の成果物に保存されます。

## 値とシークレット

**ブラウザーが入力する値** には、顧客番号、ワークフローの入力、パスワードなど、ステップが入力するものを登録し、指示の中では `%name%` と書きます。モデルが目にするのは名前だけです。機密の値にはここでシークレットを選んでください。指示、モデル、ログのいずれにも含まれません。指示にシークレットの値が含まれるステップは、値を送らずに失敗します。

## ブラウザーの設定

- **実行をまたいでサインインを保つ** は、Cookie とストレージをこのデバイスに保存し、サインインを保ちます。バックアップにはサインインは含まれません。
- **ブラウザーウィンドウを表示する** は、組み立て中に便利です。スケジュール実行では非表示にしてください。表示したままだと、作業中に Chrome が開きます。
- **スクリーンショットを保存**：**ステップが失敗したとき**、**ステップが失敗したときと、最後に**、**各ステップの後**、**なし** から選びます。
- **許可する Web サイト** は、ブラウザーが開けるホストを `example.com` や `*.example.com` のように列挙したものに限ります。サインイン用や画像用のサーバーなど、サイトが使うホストをすべて含めてください。
- **ウィンドウの幅** と **ウィンドウの高さ** で、ページの大きさをピクセルで決めます。

## 一度だけサインインする

**一度サインインしてから収集** の例から始めます。最初のステップがウィンドウを開いてあなたのサインインを待ち、以降のステップと実行は保存されたサインインを使います。保存されたサインインは **プロジェクト設定 → ストレージ → サインイン** に一覧され、**サインインを削除…** で削除できます。復元したデバイスでは、シークレットと同じように、もう一度サインインを求められます。

保存されたサインインを共有する実行は、順番に実行されます。項目を同時に処理するループでは共有できないため、1 項目ずつ処理するか、サインインの保存をオフにしてください。

## リプレイ

うまくいった操作は記憶され、以降の実行ではモデルに尋ねずに再現されます。速く、モデルの費用もかかりません。サイトが変わって再現した操作がうまくいかない場合は、あらためてモデルに尋ねます。**毎回あらためて判断する** で操作ごとにリプレイを止められ、**プロジェクト設定 → ストレージ → リプレイキャッシュ** で、サイトのリニューアル後などに記憶した操作を消去できます。実行には、各ステップの操作のうちいくつが再現されたかが表示されます。**情報を集める** と自然な言葉による確認は、毎回モデルに尋ねます。

## 多くの項目を処理する

- **スプレッドシートのリスト**：注文番号などをワークフローの入力にし、[バッチシート](/ja/docs/batches/)から項目ごとに 1 行ずつ実行します。結果列に各実行で見つかった値が集まり、シートには進み具合、失敗、残り時間が表示されます。
- **1 回の実行の中のリスト**：ステップを **各項目を処理** のループに入れます。
- **スケジュール**：[スケジュール](/ja/docs/scheduling/)を追加し、ブラウザーウィンドウを非表示にして、実行の失敗や回答待ちを[アラート](/ja/docs/alerts/)で知らせるようにします。

## 質問に答える

**私に入力を求める** は実行を一時停止します。**実行とログ → 待機中** または通知から開き、**回答** するか、**却下** でステップを失敗にします。回答は実行とともに記録されるため、パスワードではなく、すぐに無効になるコードに使ってください。回答する前にブラウザーが閉じた場合は、**ブラウザーステップを再開する** で最初の操作からやり直します。

## 費用とプライバシー

モデルが扱う操作ごとに、ページに表示されているテキストとレイアウトがモデルのプロバイダーに送られ、そのプロバイダーの料金がかかります。ステップには使ったトークン数が表示されます。再現された操作と、ページを直接読む確認には費用がかかりません。ブラウザーが入力する値とシークレットがモデルに送られることはありません。

## 制限

- このコンピューター上の Chrome またはほかの Chromium 系ブラウザーで実行します。スケジュール実行には、コンピューターが起動している必要があります。
- 自動操作のブラウザーを拒否するサイトもあります。保存したサインインや、Cookie のバナーを過ぎた開始ページでよくあるケースは回避できますが、CAPTCHA は解けません。
- 許可する Web サイトにはホスト名だけを指定でき、ローカルアドレスやポートは指定できません。

ステップが失敗したら、まずスクリーンショットを確認してください。[トラブルシューティング](/ja/docs/troubleshooting/#a-website-step-fails)も参照してください。
