## ターミナルでは動くコマンドが Kitewell では失敗する

アプリケーションの環境は、対話型シェルの環境と異なる場合があります。実行ファイルは絶対パスで指定し、作業フォルダーを設定し、必要な変数は明示的に指定してください。コマンドが対話型のプロンプトや、シェルのセッション内にしか保存されていない認証情報を必要としていないかも確認してください。

## スケジュールしたジョブが実行されなかった

保存済みのスケジュールが有効になっていること、タイムゾーンが正しいこと、プロジェクトのエンジンが実行中であること、そしてコンピューターがスリープしておらず、ユーザーがログインしていたことを確認してください。取りこぼしたスケジュールが後で実行されると考える前に、ワークフローの**スケジュール → 取りこぼしたスケジュール**とワークフローの既定値を確認してください。

**概要** には、スケジュールされた作業を止めている原因も表示されます。停止しているプロジェクトのエンジン、エンジンが受け付けないワークフロー（ほかのワークフローは実行を続けます）、一時停止の状態で届いたワークフロー、このデバイスでまだ値が必要なシークレットです。

## 実行が失敗した

**実行とログ** から実行を開きます。**失敗を確認** で失敗したステップとそのログを確認できます。**エディターで修正** でワークフローを直し、選んだステップから実行を続けられます。**アシスタントに聞く** を選ぶと、原因を調べてもらえます。[失敗の診断](/ja/docs/ai/#failure-diagnosis)がオンの場合は、もう一度試すべきか、何に対応が必要か、何を変えるべきかが表示されます。[実行とログ](/ja/docs/runs/#fix-a-failed-run)を参照してください。

<a id="a-website-step-fails"></a>

## Web サイトのステップが失敗する

まず、実行の成果物にあるステップのスクリーンショットを確認してください。サインインページ、Cookie のバナー、ボット対策の確認が原因であることがよくあります。次の点も確認してください。

- Chrome がインストールされ、**ブラウザーを確認** が成功すること
- **許可する Web サイト** を設定している場合は、ページが使うホストが含まれていること
- 待機時間がページの読み込みに十分であること
- 指示にシークレットが含まれていないこと（**ブラウザーが入力する値** を使います）
- ステップまたはワークフローでモデルが選ばれていること

サイトが変わって、再現した操作がうまくいかなくなった場合は、**プロジェクト設定 → ストレージ → リプレイキャッシュ** で消去します。[Web サイトを自動操作](/ja/docs/browser/)を参照してください。

<a id="a-desktop-step-fails"></a>
## デスクトップのステップが失敗する

まず、実行の成果物にあるステップのスクリーンショットを確認してください。次の点も確認してください。

- **デバイス設定 → デスクトップ自動操作 → デスクトップへのアクセスを確認** で、すべての許可が与えられていること。macOS では **Kitewell Agent** に画面収録とアクセシビリティの許可が、Windows では Kitewell がサービスとしてではなくサインイン中のセッションで動いていることが必要です
- 画面のロックが解除され、コンピューターがスリープしていないこと。ロック中はすべてのデスクトップステップが失敗します
- Windows で、Kitewell が管理者でないのにアプリが管理者として動いていないこと
- タスクが **タスクごとの最大操作数** に収まっていること。収まらなければ小さなタスクに分けます
- モデルがコンピューター操作ツールを備えていること。または、ステップが **汎用ツール（どの画像対応モデルでも可）** を使っていること
- 指示にシークレットが含まれていないこと（**ステップが入力する値** を使います）

デスクトップが空くのを待ったステップは、あなたのマウスやキーボードの操作で一時停止しています。誰も作業しないコンピューターでは、**デスクトップ設定** で待ち時間を短くするか無効にします。アプリが変わって、再現したタスクがうまくいかなくなった場合は、**プロジェクト設定 → ストレージ → リプレイキャッシュ** で消去します。[デスクトップアプリを自動操作](/ja/docs/desktop/)を参照してください。

<a id="google-says-this-app-is-blocked"></a>
## Google に「このアプリはブロックされます」と表示される

Google が Kitewell の Gmail アクセスの審査を終えるまで、ほとんどのアカウントでブラウザーでのサインインはブロックされ、そのページから先には進めません。ページを閉じて Kitewell に戻り、**代わりにアプリパスワードを使う** を選んでください。[メールを自動化](/ja/docs/email/)を参照してください。

<a id="a-mailbox-needs-reconnecting"></a>
## メールボックスの再接続が必要

このコンピューターでサインインできないメールボックスを指定した実行は拒否され、概要にどのアドレスを接続または再接続すべきかが表示されます。**メールアカウント** を開き、**再接続** を選んでください。よくある原因：

- アカウントのパスワードが変わった、または管理者がセッションを取り消した
- Google のサインインが 6 か月間使われなかった、または Microsoft のサインインの更新から 90 日以上たった（コンピューターが停止していた）
- プロバイダーのサイトでアプリパスワードが削除された
- Microsoft 365 の管理者が IMAP または認証済み SMTP を無効にした、または Kitewell に管理者の承認を求めている。エラーに、管理者に送るリンクが含まれます
- Google Workspace の管理者がサードパーティアプリをブロックしている

同僚や Dagu Cloud から届いたプロジェクトでは、ここで接続するまでメールボックスは未接続と表示されます。[メールを自動化](/ja/docs/email/)を参照してください。

## 実行が履歴に見当たらない

実行履歴の保存期間より古い実行は削除され、編集権限を持つユーザーは実行を削除できます。[実行とログ](/ja/docs/runs/#delete-runs)を参照してください。

## Docker を利用できない

ローカルの Docker デーモンを起動し、ワークフローエディターで **Docker を確認**を使います。Kitewell は Docker のインストールや起動を行いません。マウントやファイルパスが、コンテナを実行するマシン上に存在することを確認してください。

## AI タスクが失敗する

エージェントがインストールされてサインイン済みであること、または選択したモデルに有効なプロバイダーの認証情報があることを確認してください。**エージェントとモデル**の**エージェントをテスト**と**モデルをテスト**で、実行前にこれを確認できます。記録されたプロンプト、タスクの stderr、プロバイダーの制限、請求状況を確認してください。実際の認証情報は Issue の報告に含めないでください。

## 更新の確認に失敗する

ネットワークと[リリース状況](/ja/releases/)を確認してください。公開アップデートフィードは、最初の公開リリースまでは有効になっていません。チェックサムやインストーラーの検証が失敗し続ける場合は、回避せずに報告してください。

## Windows に SmartScreen の警告が表示される

新しい発行元のインストーラーに対して、Windows が警告を表示することがあります。ダウンロードしたファイルの SHA256 が[ダウンロードページ](/ja/download/)の値と一致することを確認してから、**詳細情報 → 実行** を選んでください。インストーラーの署名が無効だと Windows が表示した場合は、実行せずに[報告](/ja/support/)してください。

## Kitewell が WebView2 のインストールを求める

Kitewell のウィンドウには Microsoft Edge WebView2 ランタイムが必要です。未インストールの場合はインストーラーが導入します。それでも WebView2 がない状態で Kitewell が開いた場合は、ウィンドウの **Install WebView2** を選んでください。Microsoft からダウンロードされ、1 分ほどで完了します。

## ログを探す

タスクの失敗は、まず**実行とログ**で確認します。サービスとプロジェクトのエンジンのログを表示、検索、ダウンロードするには、**このデバイス → 診断**を開きます。各ログは 10 MiB でローテーションされ、3 つのアーカイブが保持されます。サービスのログは、macOS では `~/Library/Application Support/Kitewell/logs`、Windows では `%LOCALAPPDATA%\Kitewell\logs` にあります。Windows の `shell.log` には、起動、再起動、終了など、アプリ自体の動作も記録されます。

ガイドで問題が解決しない場合は、バージョン、再現手順、機密情報を取り除いた出力を添えて、[サポートの Issue を作成](/ja/support/)してください。
