---
title: アラート
---

アラートは、ワークフローに対応が必要になったときに知らせます。状況を確かめるために Kitewell を開いたままにしておく必要はありません。アラートは Kitewell Pro の機能です。無料プランでは、代わりに**通知**にアップグレードの案内が表示されます。

## チャンネルを追加する

**このデバイス**の下にある**通知**を開きます。チャンネルとは、アラートの送信先です。

- **このデバイス**は、macOS のデスクトップ通知を表示します。**このデバイスで通知**をオンにし、macOS から確認されたら通知を許可してください。
- **メール**は、同じページで設定した**メールサーバー**を通じて、受信者のリストに送信します。サーバーは TLS または STARTTLS に対応している必要があります。プロバイダーが求める場合は、アプリパスワードを使用してください。
- **Slack** は、Incoming Webhook を通じてチャンネルに投稿します。
- **Microsoft Teams** は、Webhook 要求を受信したときにチャンネルへ投稿するテンプレートから作成したワークフローを通じて投稿します。
- **PagerDuty** は、Events API v2 のインテグレーションキーを使ってインシデントを作成し、問題が解消するとそのインシデントを解決します。
- **Webhook** は、[Standard Webhooks](https://www.standardwebhooks.com/) 形式の署名付き JSON を任意の受信先に送信します。署名シークレットは、チャンネルの作成時に一度だけ表示されます。

**テスト送信**は、入力した値を保存する前に、その値でサンプルのアラートを送信します。各チャンネルには最後の送信が届いたかどうかが表示され、**最近の通知**には送信済みのアラートと再試行中のアラートが一覧表示されます。

## 知らせる内容を選ぶ

ルールによって、どのイベントをどのチャンネルに送るかが決まります。

1. **通知**ページの**既定の通知ルール**は、独自のルールを持たないすべてのプロジェクトに適用されます。
2. **プロジェクト設定 → 通知**では、1 つのプロジェクトに独自のルールを設定できます。
3. ワークフローのエディターまたは**ジョブ**一覧にあるベルから、そのワークフローを 1 時間、1 日、1 週間、または解除するまでミュートしたり、独自のルールを設定したり、実行が長時間とみなされる基準を設定したりできます。これらの変更はすぐに適用され、ワークフローの定義は変わりません。

## イベント

- **失敗したとき**：最後の自動再試行の後に通知します。失敗した実行のたびではなく、失敗が続き始めたときに通知し、次の実行が成功すると**復旧**として再び通知します。
- **入力待ちのとき**：人が対応するタスクまたは承認が、誰かの対応を待っています。
- **スケジュール実行を逃したとき**：スケジュールされた実行が開始されなかったことを、その回数と理由（コンピューターがスリープしていた、Kitewell が起動していなかったなど）とともに通知します。再び時間どおりに実行されると、続いて **Schedule resumed** が届きます。
- **長時間実行されているとき**：実行が、最近成功した実行にかかった時間を大きく超えて、またはワークフローに設定した上限を超えて、まだ続いています。
- **キャンセルされたとき**と**成功したとき**：送信先を設定しない限りオフです。

PagerDuty に送られるのは、失敗、スケジュールの取りこぼし、長時間の実行だけです。これらは後で解消されるアラートだからです。

## アラートの内容

アラートには、プロジェクト、ワークフロー、失敗したステップの名前が含まれ、終了コードや時間制限が原因の場合はその値も含まれます。ステップの出力や実行パラメーターは含まれません。リンクからは、その実行を行っているコンピューター上の Kitewell で実行を開きます。

アラートは、コンピューターがスリープしていない間にバックグラウンドサービスから送信されます。送信できなかったアラートは、最大 1 日再試行されます。Kitewell は外部からコンピューターを監視しません。コンピューターがスリープ中または電源オフの場合は、復帰するまで何も送信されず、取りこぼしたスケジュールはその時点で通知されます。

## アラートとイベントハンドラー

[イベントハンドラー](/ja/docs/workflow-builder/#run-a-task-when-the-workflow-ends)は、ワークフローが成功、失敗、キャンセル、または終了したときに実行されるタスクで、後処理や復旧に使います。人に知らせるには、ハンドラーではなくアラートを使ってください。ワークフロー定義では、エンジン自体のメール設定（`mail_on`、`smtp`、`error_mail`、`info_mail`、`mail_on_error`）は設定できません。アラートは Kitewell で設定します。
