---
title: ワークフローを組み立てる
---

各タスクで何をするかを選び、ステップをつないでワークフローを組み立てます。タスクでは、コマンドやスクリプト、Docker イメージ、AI エージェント、モデル、AI による判断を実行できます。ほかにも、テキストテンプレートへの値の埋め込み、Web サービスやインポートした API の呼び出し、別のマシンでの実行やそのマシンとのファイルのコピー、人への依頼、別のワークフローの実行、値による分岐、項目ごとの繰り返し、待機、条件に一致するまでの繰り返しができます。これらはすべて 1 つのワークフローに混在させられます。グラフには実行順序が表示され、ステップを選択するとその横に設定が開きます。

<a id="example-build-a-daily-report"></a>
## 例: 日次レポートを作成する

注文の CSV を読み込み、Python で合計を計算して、Markdown のレポートを保存します。この例では 3 件のサンプル注文を使い、すべてお使いのコンピューター上で実行します。Python 3 が必要です。

**Read orders → Build report → Save report**

### サンプルを準備する

`daily-report` という名前のフォルダーを作成します。そこに [orders.csv](/examples/orders.csv) をダウンロードするか、次のテキストを `orders.csv` として保存します。

```csv
order_id,amount_usd
1001,1200.00
1002,800.00
1003,450.00
```

**ジョブを作成** を選び、名前を **Daily sales report** にして、**ツール → YAML を編集** を開きます。内容を次のワークフローに置き換え、`working_dir` を `daily-report` フォルダーの絶対パスに変更します。

[ワークフローの YAML](/examples/daily-report.yaml) をダウンロードすることもできます。

```yaml
type: graph
# Replace this with the absolute path to the folder containing orders.csv.
working_dir: /absolute/path/to/daily-report
steps:
  - id: read_orders
    name: Read orders
    run: cat orders.csv
    output: ORDERS

  - id: build_report
    name: Build report
    depends: [read_orders]
    run: |
      #!/usr/bin/env python3
      import csv
      import io
      import os
      from decimal import Decimal

      orders = list(csv.DictReader(io.StringIO(os.environ["ORDERS"])))
      revenue = sum(Decimal(order["amount_usd"]) for order in orders)
      print("# Daily sales report\n")
      print(f"- Orders: {len(orders)}")
      print(f"- Revenue: ${revenue:,.2f}")
      print(f"- Average order: ${revenue / len(orders):,.2f}")
    output: REPORT

  - id: save_report
    name: Save report
    depends: [build_report]
    run: |
      printenv REPORT > report.md
      cat report.md
```

Kitewell が `python3` を見つけられない場合は、ターミナルで `command -v python3` を実行して表示される絶対パスで `/usr/bin/env python3` を置き換えてください。

### 実行して結果を確認する

**ツール → ビジュアルエディター** を選ぶと、3 つのステップが表示されます。**Read orders** は CSV を `ORDERS` として保存し、**Build report** はその値を読み取って結果を `REPORT` として保存します。各ステップは、前のステップが終わるのを待ちます。

**ツール → ワークフローを確認** を選び、続けて **確認して実行 → 保存して実行… → 実行を開始** を選びます。**実行とログ** を開いて **Save report** を選択します。出力は次のようになります。

```markdown
# Daily sales report

- Orders: 3
- Revenue: $2,450.00
- Average order: $816.67
```

同じテキストが `daily-report` フォルダーの `report.md` に書き込まれます。このファイルは実行のたびに置き換えられます。`orders.csv` の金額を変更してもう一度実行すると、合計が変わることを確認できます。

手動での実行がうまくいったら、**スケジュール** を開いて毎日の実行時刻とタイムゾーンを選びます。その時刻には、コンピューターをスリープさせず、Kitewell を起動したままにしてください。バックグラウンドでの動作と実行の取りこぼしについては、[スケジュール](/ja/docs/scheduling/)を参照してください。

### 独自のステップを追加する

**組み立て** で **+** を使うと、タスクを追加できます。**この後に流れを続ける** は、後続のステップの前にタスクを挿入し、後続のステップはそのタスクを待つようになります。**次の位置に分岐を追加** は、別の経路を作成します。**独立して開始** は、そのステップを待たない処理を追加します。

## インポートした API を使う

[OpenAPI 仕様を API ライブラリにインポート](/ja/docs/apis/)してから、ワークフローに **API アクションを使う** を追加します。接続済みの API とオペレーションを選びます。Kitewell は、必須パラメーターやリクエストボディを含むリクエストのフィールドを仕様から作成します。

後続のステップで **変数** を開き、API ステップのレスポンスのフィールドを選びます。Kitewell は値を保存し、結果が使われる前にリクエストが完了するようにステップをつなぎます。

## Docker イメージを実行する

デバイスで Docker を起動します。タスクの選択画面で **Docker で実行** を選びます。

1. タグを含めて **イメージ** を選びます。イメージの候補を検索するか、**イメージを探す** を使います。**検査** はイメージのポート、フォルダー、変数を読み取り、ステップの設定を手助けします。
2. イメージ内で実行するコマンドを入力します。複数行、パイプ、シェル変数を使う場合は **シェルスクリプト** を使います。その場合、イメージに `/bin/sh` が含まれている必要があります。
3. 作業フォルダー、マウント、環境、公開ポート、ネットワークなど、必要なオプションを展開します。コンテナー内で作成したファイルをコンテナーの外でも使えるようにするには、マウントが必要です。
4. **Docker を確認** で接続を確認します。**Run this step** は設定したイメージとコマンドを実際に実行するため、先にマウントと影響を確認してください。

Kitewell は Docker をインストールしたり起動したりしません。**実行後もコンテナーを残す** を有効にしない限り、コンテナーは実行後に削除されます。マウントしたファイルと Docker ボリュームは、別途バックアップが必要です。

## AI エージェントやモデルに依頼する

**エージェントとモデル** で名前付きのエージェントまたはモデルを設定してから、ワークフローに追加します。

- **AI エージェントに頼む** は、インストール済みのコマンドライン型エージェントを実行します。エージェントを選択してプロンプトを書き、**エージェント設定とコンテキスト** でプロジェクトフォルダーと任意のコンテキストを設定します。
- **モデルに尋ねる** は、設定済みの API モデルにプロンプトを直接送信します。モデルを選択し、必要な回答の内容を記述します。

後続のステップで結果が必要な場合は、結果を変数として保存します。対応するフィールドで `${` と入力すると、ワークフローの入力、シークレット、前のステップの結果を選択できます。結果を使うステップが、その結果を生成するステップを待つようにしてください。

**ツール → AI プロンプトを確認** では、実行前に記述した指示を確認できます。実行時の値は、ワークフローの実行時に埋め込まれます。認証情報、権限、プロバイダーの要件については、[AI エージェントとモデル](/ja/docs/ai/)を参照してください。

## 人の対応を待つ

**人に依頼する** を選ぶと、指示と、必要に応じてフォームを追加できます。タスクでは、確認を求めたり、選択肢、コメント、数値などの値を入力してもらったりできます。誰かがタスクを完了するまで、実行は待機します。

自動で実行されるステップの結果をレビューするには、そのステップの **承認** セクションを開き、**このステップの実行後に承認を待つ** を有効にします。質問と、入力してもらう値を入力します。**差し戻し時に再実行するステップ** では、レビュー担当者が変更を求めたときに繰り返すステップを選択します。

承認ゲートは、ステップの実行**後**に一時停止します。リモートコマンドなどの操作の前に許可を必須にするには、その操作の前に **人に依頼する** タスクを置くか、それより前の準備ステップに承認を設定します。

一時停止中の実行は **実行とログ → 待機中** にあります。そこから **あなたの対応待ち** を開きます。人によるタスクでは **タスクを完了** を選べます。承認ゲートでは **承認**、**差し戻す**、**実行を却下** のいずれかを選べます。差し戻すと、選択したステップとそれ以降の処理が再実行されます。却下すると実行は終了します。

## サーバーやグループでコマンドを実行する

プロジェクトのサイドバーで **サーバー** を開きます。各サーバーのアドレス、ユーザー名、認証情報を追加します。パスワードは[シークレット](/ja/docs/secrets/)に保存するか、ローカルの秘密鍵を使います。デフォルトの承認済み鍵による検証を使う場合は、**接続をテスト** でホストのフィンガープリントを確認して承認します。

グループを作成すると、複数のサーバーを 1 つの実行先にまとめられます。サーバーを必要な順序に並べ、同時に実行できる数を選び、失敗時にロールアウトを停止するか続行するかを選びます。

ワークフローに **別のマシンで実行** を追加します。**実行先** でサーバーまたはグループを選択し、リモートで実行するコマンドを入力します。グループを選ぶとマシンごとに個別のステップが作られるため、結果は **実行とログ** にマシンごとに表示されます。

すべてのコマンドステップとスクリプトステップを同じ実行先に送るには、ワークフローの **設定 → 実行先** を使います。ここでグループを指定すると、ワークフローが各マシンで順番に実行され、マシンごとに個別の実行になります。Docker、AI、HTTP、インポートした API、サブワークフローのステップは、引き続き Kitewell を実行しているデバイスから実行されます。この設定でエンジン全体がサーバーに移るわけではありません。

<a id="run-a-task-when-the-workflow-ends"></a>
## ワークフローの終了時にタスクを実行する

イベントハンドラーは、ワークフローのステップとは別に実行されるタスクです。最初のステップの前、実行が承認を待っている間、成功時、失敗時、キャンセル時、または終了時に常に実行できます。一時ファイルの削除、変更のロールバック、復旧用サービスの呼び出しなどに使います。

グラフの下にある **イベントハンドラー** に、このワークフローのハンドラーが一覧表示されます。**ハンドラーを追加** を選んで実行するタイミングを選ぶと、ハンドラーが単独でステップエディターに開きます。**タスクの種類** は、コマンド、スクリプト、Docker イメージ、AI エージェントまたはモデル、テキストテンプレート、HTTP リクエスト、インポートした API アクション、SSH コマンド、ファイル転送、別のワークフローに変更できます。人によるタスク、AI による判断、分岐、ループ、待機、繰り返しはハンドラーにできません。**← ワークフロー** を選ぶとグラフに戻ります。

ハンドラーでは、ワークフローの入力と変数、実行のステータスを使えますが、ステップの結果は使えません。**実行とログ** では、実行ごとにステップと並んでハンドラーが表示されます。ハンドラーを選択すると、その出力を確認できます。

ワークフローの失敗を人に知らせるには、ハンドラーではなく[アラート](/ja/docs/alerts/)を使います。

<a id="check-run-and-schedule"></a>
## 確認、実行、スケジュール設定

**ツール → ワークフローを確認** で下書きを検証します。**確認して実行** では、スケジュール、入力、タスクの詳細をまとめて確認できます。**保存して実行…** はワークフローを保存して入力フォームを開き、**実行を開始** で実行が始まります。

**実行とログ** を開いてステップを選択すると、その出力を確認できます。手動での実行がうまくいったら **スケジュール** を設定し、保存済みのスケジュールを有効にします。デバイスの稼働状況と実行の取りこぼしについては、[スケジュールとバックグラウンド動作](/ja/docs/scheduling/)を参照してください。
