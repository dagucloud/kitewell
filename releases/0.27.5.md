Kitewell 0.27.5 is a beta update, with the Dagu 2.27.0 engine.

## What's in this release

- Flow tuning: when a workflow's run fails, Kitewell finds out why on its
  own, fixes the workflow, runs the steps up to the one that failed to see
  the fix works, saves it, and says in the project's chat what failed and
  what changed. When the cause lies outside the workflow, such as a site
  that is down or a sign-in that expired, it changes nothing and says what
  you need to do. A run you started from a chat card is fixed the same
  way. Turn Flow tuning off in the project's settings.
- A site you let Kitewell's browser open is allowed for the whole project:
  nobody in the project, on any computer, is asked about it again. Project
  settings list the allowed sites, let you allow one by name or address,
  and remove one so Kitewell asks again. Sites your saved workflows open
  are allowed already, and are listed with the workflows that open them.
- Japanese and Chinese now say フロー and 流程 for a workflow, the words
  RPA tools use. The button that opens the chat says Create a workflow, and
  a failed or skipped step offers Find out why.
- Project settings show and save "Asking before a change" and Flow tuning
  for the project you are looking at; they used to change the first
  project's.
- A red button such as Cancel run stays readable under the pointer.

## Upgrading

Nothing to do. Kitewell updates itself to 0.27.5 at a quiet moment, and
running workflows go on across the restart. Sites a chat allowed before
become its project's allowed sites as Kitewell starts. In a project
shared with others, update everyone's Kitewell to 0.27.5: saving project
settings in an earlier version clears the allowed sites.
