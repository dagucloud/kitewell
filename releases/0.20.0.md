Kitewell 0.20.0 is a beta update.

## What's in this release

- Desktop steps on a Mac now work with an app's buttons, fields, lists, and
  checkboxes through macOS Accessibility, as on Windows. A step Kitewell
  learned replays by finding the same control again instead of clicking a
  spot on the screen, so a moved window, another display, or a title that
  changes with the document still replays without asking the model. Dropdown
  options are chosen by name, and controls in apps built on Electron are
  found too.
- A desktop step that meets a screen your workflow did not expect stops
  there. It no longer brings its window forward over an unanswered dialog;
  the run says what the dialog asks instead.
- A desktop step can answer a screen an app shows only sometimes, such as
  「入力内容をクリアします。よろしいですか？」 after a reset, whenever it
  comes up, and runs where it never appears wait nothing for it. A part only
  some runs need, such as a second contact, can depend on the run's inputs,
  decided without the model, so one workflow covers every case. A check can
  also tell whether a button or field is grayed out. Kitewell writes desktop
  workflows this way, with a step per screen and checks before anything is
  submitted, so a failed run can be retried from the step that failed.
- Desktop steps are steadier. They read and act only once the window stops
  changing, which keeps apps that rebuild their window from crashing mid-step;
  look again while no window is in front; bring a window that is behind
  another forward before clicking it; and scroll reliably. When you use the
  mouse or keyboard during a step, it waits for you to stop and then returns
  to the app it was working in. A checkbox a pinned step sets is left checked
  or unchecked as recorded, rather than clicked.
- **Google Calendar** is built into the API library. Connecting it takes one
  click: Kitewell adds the connection and opens Google's sign-in, and the
  connection names the Google account that signed in. It reads your calendars
  and when you are busy; reading events comes once Google completes its review
  of Kitewell's access. Disconnecting a Gmail mailbox no longer ends a calendar
  connection of the same Google account.
- A Google sign-in for an API connection now stays connected. It used to end
  after an hour.
- API specifications converted from Google's API documents import as
  expected: their actions are no longer marked unsupported, and each is named
  by what it does instead of by its path.
- A run you open in **Runs & logs** while it runs is now followed: the view
  selects the running step, keeps its output at the newest line, and scrolls
  the diagram and step table to it. A step waiting for you comes first, and a
  finished run lands on the failed step's errors or the step that ran last.
  Anything you do there hands the view back to you; **Follow live** turns
  following on again.
- A change the assistant proposes to a workflow shows its diff right in the
  proposal card, with long stretches of unchanged lines folded.
- When the assistant works a website, it asks once per site rather than once
  per host, so a sign-in that moves between www., accounts., and app. of one
  site asks once.
- An alert for a run that stopped because the included model's credits ran
  out now says so, instead of only naming the step that failed.

## Upgrading

Nothing to do. Kitewell 0.19.0 updates itself to 0.20.0 at a quiet moment,
and running workflows go on across the restart.
